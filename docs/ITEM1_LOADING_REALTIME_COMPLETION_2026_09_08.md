## 실제 사용 방법

- 메뉴 이동은 저장된 결과를 먼저 읽는다. 수급 메뉴 진입만으로 수집 POST를 시작하지 않는다.
- 가격만 확인할 때 상단 **화면 종목 가격 확인**을 누른다. 현재 메뉴에서 렌더링된 종목 최대 50개를 확인한다. 화면 아래쪽 행도 포함될 수 있다.
- 표의 원래 값은 분석 기준 종가이고, 그 아래 추가되는 값은 NAVER 조회 가격·시각이다. 순위, 피크 환산값, 시즌 수익률은 이 버튼으로 재계산하지 않는다.
- 원천 일봉과 점수 자체를 최신화하려면 기존 실행 파이프라인의 수집·재계산 결과를 확인해야 한다.
- 공개판은 배포된 저장본을 사용한다. 로컬 가격 API를 연결한 것처럼 표시하지 않고 외부 차트 확인을 안내한다.

## 성능 및 동등성 근거

아래 숫자는 이 PC·현재 저장 자료·현재 캐시 상태에서 측정한 값이다. 인터넷 사용자 지연이나 모든 캐시 초기화 상태의 보장값이 아니다. Chrome DevTools 전용 성능 도구가 없어 web-perf 정밀 추적은 중단하고 HTTP/Playwright 대체 검사를 사용했다. Lighthouse/Core Web Vitals 인증으로 인용하면 안 된다.

### 실제 브라우저 메뉴 렌더 완료

페이지를 새로고침한 뒤 메뉴를 순서대로 방문했다. 앱의 `data-load-ms`를 읽었으며 자동화 클릭/CLI 실행 시간은 제외했다. 서버 캐시·디스크 캐시는 유지한 상태다.

이 11개 메뉴 이동 중 POST 요청은 **0건**이었다. 자동 수집·주문을 시작하는 검사도 수행하지 않았다. 이전 확인에서 관심종목 20.455초, 스마트 수급 4.290초, 시장국면 전체 응답 대기 14.128초가 관측됐다. 전후 캐시 조건이 같지 않으므로 엄밀한 개선율로 계산하지 않는다.

시장국면은 KRX 부분 결과를 먼저 표시하고 거시지표를 뒤이어 연결한다. 부분 결과에는 이를 명시하고, 종합 결과 저장 파일을 덮어쓰지 않는다. 외부 제공처 지연은 남을 수 있다. 가격 파일 또는 모델이 바뀐 최초 계산은 약 5초가 필요할 수 있다. 준비된 디스크 캐시 자체 조회는 0.001초, 서버 재시작 후 KRX 부분 HTTP 응답은 190ms였다. 파일 버전·모델 해시·캐시 내용 해시를 검증하고 손상된 캐시는 다시 만든다.

## 공개용 파일

현재 canonical 시즌 저장본을 로컬 검증 폴더에 준비한 뒤 오프라인 최적화를 적용했다. 기존 `dist-public`은 변경하지 않았다.

| 자료 | 이전 바이트 | 경량화 후 바이트 | 의미 |
| --- | ---: | ---: | --- |
| 시즌 전체 파일 → 필터 인덱스 | 24,986,945 | 1,074,359 | 설명은 관련 목록 청크, 상세는 종목 클릭 시 추가 조회 |
| 수급 | 2,538,118 | 1,077,616 | 중복 행 복원 가능, 같은 종목의 다른 값은 병합하지 않음 |
| 선취매 카드 | 1,891,086 | 625,329 | 상세는 같은 세대·신호로 별도 연결 |

시즌의 총 데이터 자체를 삭제한 것이 아니다. 초기 일괄 다운로드를 나누었다. 필터 결과가 흩어져 있으면 한 페이지가 여러 50행 청크를 읽을 수 있다.

- `node scripts/build-public.mjs --reuse-data --out=output/item1-public`: 3,624개 파일, 기존 비밀정보 검사 통과.
- Chromium에서 이 빌드의 파일을 요청별로 직접 제공하는 로컬 미리보기로 목록 50개, 다음 페이지, 상세 플레이북 연결을 확인했다. 공개 CDN/실제 전송속도 검사는 아니다.
- 임시 503 응답 후 재시도 성공을 확인했다. 실패 Promise가 계속 캐시에 남는 문제를 수정했다.
- 지원하지 않는 검증 기간·세대 불일치는 명시적으로 거절한다. ID가 없는 레거시 자료에 신호 ID를 만들어 붙이지 않는다.
- 상세 제목/차트 버튼의 줄바꿈을 보완하고 최종 캡처를 확인했다: `output/playwright/item1-public-detail-final.png`.

## 해결되지 않은 문제 — 다음 묶음에서 다룰 것

1. **KRX 원천 수집 지연:** 확인 시 저장 종가·점수 기준일은 9월 4일, 별도 가격 제공처에서는 9월 7일 종가가 조회됐다. 파이프라인에는 `source_not_ready` 이력이 있다. 로딩 개선으로 누락된 일봉을 채운 것은 아니다. 오래된 값을 최신으로 표시하지 않도록 고쳤다.
2. **외부 가격 제공처:** NAVER 공개 웹 조회 경로는 SLA가 보장된 증권사 실시간 스트림이 아니다. 3초 타임아웃·15초 캐시·결측 표시를 적용했고 `realtime_verified=false`다. 변경·차단·지연 가능성은 남는다. KIS 토큰을 발급하거나 보안 설정을 변경하지 않았다.
3. **2번 통합·복구·배포 검증:** 전체 메뉴의 기준일/누락 자료/실패 복구와 운영 공개 배포를 따로 확인해야 한다. 공개 상세 12개월 히트맵의 미제공 값 등 기존 자료 공백도 여기서 점검한다. 현재 공개 사이트에 이번 코드가 올라갔다고 보면 안 된다.
4. **3번 역사적 신뢰성:** 과거 유니버스·기업행위·비용·당시 공시/이벤트 입력과 전체 독립 OOS 검증은 별도 데이터 의존 과제다. 성능 개선과 선정 결과 동등성은 투자 수익 신뢰성 인증이 아니다.
