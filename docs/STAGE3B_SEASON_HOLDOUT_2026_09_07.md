## 결론과 확인 위치

**전체 기간 선택 오류는 수정했다. 시즌의 월·종료일 선택을 과거 연도와 이후 연도로 분리하는 진단 기준모형도 추가했다. 다만 기존 선취매 전체 전략의 OOS 검증을 완료한 것은 아니다.**

확인: 시즌 모멘텀·캘린더 → 종목의 상세 플레이북 → **연도 분리 진단 · 과거 자료로만 월·종료일 선택**을 펼친다. 날짜·사유·가격 변화가 연도별 카드로 표시된다. 접힌 상태에서는 진단 API 요청이 없다. 공개판은 로컬 전용 안내만 표시한다.

이 결과는 `RECONSTRUCTED_REFERENCE_RULE` / `TEMPORAL_HOLDOUT_RAW_DIAGNOSTIC`이다. 실제 당시의 선정 기록이나 미열람 잠금 검증이 아니라, 현재 보유한 시세로 재구성한 월 선택 기준모형이다. 인과적 촉매, 수익성 보장 또는 실전 승률을 뜻하지 않는다.

## 1. 실제 오류 수정

- `remaining_peak.py`의 `[-max(1, int(lookback_years)):]`가 0을 1년으로 처리했다. 0은 모든 유효 역사 표본을 사용하고 양수만 해당 개년 수로 자르도록 수정했다. 중복 슬라이싱도 제거했다.
- 상세 조회의 `currentV11Lookback || 5`가 0을 5년으로 덮어썼다. `?? 5`로 수정해 0을 보존했다.
- 발견 캐시 버전을 6→7, remaining-peak 서명을 1→2로 변경했다. 예전 1년 계산 결과를 새 전체 기간 결과로 재사용하지 않는다.
- 실제 삼성전자 일봉, 2026-09-07 조회 기준으로 전체 기간 표본 10개년 / 최근 5년 표본 5개년을 확인했다.
- 전체 기간 저장본 4,451패턴을 145.65초에 준비했다. 기본 5년 저장본은 3,775패턴이며 준비된 파일 재사용은 0.65초였다. 두 시간은 서로 다른 작업 조건이므로 직접적인 속도 개선 비교가 아니다.

## 2. 연도 분리 기준모형의 정확한 규칙

1. 테스트 연도 1월 1일을 가상의 결정 시점으로 두고, 그 전년도 12월 31일까지의 완료 월만 학습한다. 직전 5년/3년/2년 또는 전체 기간 옵션을 적용한다.
2. 월별로 최소 3개년의 유효 표본이 필요하다. 학습 구간에서 월 첫 시가→월 마지막 종가 변화의 중앙값이 가장 큰 월을 선택한다. 동률은 작은 월 번호 우선이다. 가장 좋은 월의 중앙값도 0 이하면 그 연도는 진입하지 않는다.
3. 선택 월의 과거 최고 종가 발생일 중앙값을 계산하고 최대 28일로 제한해 종료일을 미리 고정한다.
4. 테스트 연도에는 선택 월 첫 관측 거래일 시가로 시작해 고정 종료일 이후 첫 관측 거래일 종가로 끝낸다. **테스트 연도의 사후 최고가를 찾아서 종료하지 않는다.** 종료 이후 가격을 품질 판정에 끌어들여 앞선 결과를 바꾸지도 않는다.
5. 현재 연도는 완료되지 않은 연도이므로 평가에서 제외한다. 학습 부족·양수 월 없음·진입/중간 가격 누락·무거래·가격 오류·불연속은 연도 수에서 삭제하지 않고 별도 상태로 남긴다.
6. 수정주가·기업행위·상장폐지 정산·체결 근거가 연결되지 않았으므로 원시 가격 진단만 산출한다. `verified_return=null`, `verified_count=0`이다. 가격 변화 평균은 유효 진단 표본 기준이며 연환산·누적 포트폴리오 수익률이 아니다.
7. 20/50/100bps 차감은 고정 비용 가정에 대한 단순 민감도이며 실제 세금·수수료가 아니다. UI는 50bps 가정을 원시 가격 변화와 나란히 표시한다.

**범위 제한:** 기존 선취매의 ‘피크 30일 전 진입’, 수급·현재 확인·등급·전 종목 순위 규칙을 그대로 재생한 모델이 아니다. 과거 유니버스와 상장폐지 자료도 검증하지 않았다. 특정 현재 종목의 진단을 전 종목 전략 성과로 합산하지 않는다. 다중검정·연구자 선택편향·독립 외부 기간·통계적 불확실성 검증이 남아 있다.

## 4. 저장·성능·UI

- `research/season_holdout.py`: 순수 연도 분리 계산과 표본 상태.
- `research/season_holdout_store.py`: 원천/기간/코드/날짜별 체크섬 저장본. 최초 준비는 백그라운드, 작업자 최대 2개·대기 8개로 제한한다. 동일 요청을 합친다.
- `GET /api/research/season-holdout/{ticker}?lookback_years=...`: READY/PENDING/BUSY/ERROR를 구분한다. 미준비 요청은 배경 준비를 예약하지만 HTTP 처리 안에서 연구 계산을 수행하지 않는다. 손상·원천 변경은 이전 파일을 덮어쓰지 않는다.
- 저장 경로: `data/research_snapshots/season_holdout/<report_id>.json`, Git 제외. 실행 중 코드가 바뀌면 새 코드를 읽은 프로세스로 재시작하기 전 진단 캐시를 게시하지 않는다.
- 실데이터 최초 3종목 준비 0.568 / 0.518 / 0.553초. 브라우저의 저장된 단건 응답은 약 42ms, 11.7KB였다. 전체 기간 최초 진단은 PENDING 후 재확인 1회로 표시됐다. 개발 PC의 제한적 관측이며 운영 p95/CWV는 아니다.
- 시즌 메뉴 진입 및 상세창 열기만으로 진단 API가 호출되지 않았다. 진단 패널 펼치기 후 호출됐고, 전체 기간 선택 시 `lookback_years=0`이 실제 요청에 유지됐다.
- 초기 표는 좁은 상세창에서 문구가 과도하게 줄바꿈돼 연도별 카드로 수정했다. 화면 검증 자료: `output/playwright/stage3b-season-holdout-card.png`, `stage3b-season-holdout-view.png`.

### 남아 있는 실제 로딩 병목

전체 기간 탐색 API 응답은 브라우저에서 **10,960,520byte, 약 1.81초**로 관측됐다. 큰 응답과 많은 DOM 행이 메뉴 반응에 부담을 준다. 이번 진단 API를 작게 분리한 것과 기존 전체 탐색 속도 문제가 해결된 것은 다르다. 목록은 요약·페이지 단위로, 상세는 클릭 시 별도 요청하도록 바꾸는 작업이 필요하다.
