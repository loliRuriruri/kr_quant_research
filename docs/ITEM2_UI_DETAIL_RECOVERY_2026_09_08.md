## 완료한 수정

1. **다른 종목의 늦은 응답 차단:** A 종목 조회 중 B를 열었을 때 A의 응답/오류가 B 상세를 덮어쓰는 문제를 재현했다. A 응답을 보류하고 B 오류를 먼저 표시한 뒤 A를 풀자 화면이 A 오류로 바뀌었다. 요청 번호와 상세창 수명 검사를 추가한 뒤 B 화면이 유지됐다.
2. **상세창 닫기/메뉴 이동:** 닫은 뒤 도착한 응답은 UI를 수정하지 않는다. 진행 표시도 정리한다. 늦은 요청이 새 요청의 진행 표시를 끄지 못하게 했다.
3. **AI 설명·저장 리포트 분리:** 이전 종목의 후속 설명/리포트도 현재 상세 요청에 속할 때만 표시한다. 별도 보관함에서 리포트를 여는 경로는 다른 종목 상세의 리포트 영역을 먼저 덮어쓰지 않는다.
4. **응답 종목 검사와 재시도:** 요청 코드와 결과 코드가 다르면 오류로 표시한다. 오류 화면에 ‘이 종목 다시 조회’ 버튼을 추가했다. 실제 000660 조회의 모의 503 후 버튼을 눌러 `SK하이닉스 (000660)` 상세로 복구됨을 확인했다.
5. **가격 설명 수정:** 수급/빈집 표의 저장 가격을 ‘토스 실시간 현재가’라고 설명하던 툴팁 두 곳을 저장본 기준으로 수정했다. 상단 별도 가격 확인과 구분한다.
6. **정적 자산 갱신:** JS/CSS 버전을 2.80.2로 올렸다. 재현 검사에서 같은 주소의 이전 JS가 브라우저에 남아 있어 변경 버전으로 재확인했다. 서버 엔진 재시작은 필요하지 않으며 로컬 페이지를 새로고침하면 적용된다.

요청 수명 검사는 네트워크 응답의 표시를 막는 것이며 이미 시작한 서버 작업을 취소하지는 않는다. 기존 상세 GET 경로의 외부 정보 조회/AI 설명 동작은 유지한다. 이번 테스트는 수집·점수 재계산·포트폴리오 쓰기·별도 리포트 생성 버튼을 누르지 않았다.

## 모바일에서 확인한 별도 설계 문제

390×844 좁은 Chromium 뷰포트에서 가로 스크롤이 생기고 왼쪽 메뉴가 넓은 비중을 차지했다. 원인은 `viewport width=1200`, `body`/`.screen-layout`의 `min-width:1200px`, 모바일 메뉴 숨김 규칙이다. 코드의 ‘Unified Desktop PC Layout’에 의도된 PC 화면 강제 정책이 명시되어 있다.

이번에 임의로 전체 레이아웃 정책을 반전하지 않았다. **모바일 최적화 완료가 아니다.** 다음 UI 작업에서는 기존 PC 보기/확대 기능을 보존하면서 좁은 화면용 탐색·카드·표 스크롤을 제공하는 방식으로 전환해야 한다. 전환 후 주요 메뉴별 가로 넘침/드로어/터치 접근 검사가 필요하다. 단순 CSS 한 줄로 모든 메뉴가 정상이라고 처리하지 않는다.
