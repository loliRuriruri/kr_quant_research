# 6단계 전반: 시즌 목록 서버 복사 비용 축소

작업 전 저장점 `e98e0fc`. 재개 기록의 남은 서버 bundle 복사 병목을 먼저 개선했다. 실시간 피드 추가·전 메뉴 최적화 완료는 아니다.

## 측정과 수정

전체 기간 discovery summary를 같은 로컬 자료로 함수 직접 호출 6회(첫 호출/이후 5회)했다.

- 이전: 1.467 / 0.720 / 0.739 / 0.771 / 0.804 / 0.804초. 캐시 5회 중앙값 0.771초.
- 이후: 1.030 / 0.282 / 0.226 / 0.225 / 0.297 / 0.235초. 캐시 5회 중앙값 0.235초.
- 중앙값 약 69% 감소. 이 수치는 로컬 Python 함수 시간이며 HTTP 네트워크/렌더링/LCP/INP/CWV 측정이 아니다. 실행 시점의 부하 영향을 포함하므로 전체 메뉴 성능을 대표하지 않는다.

기존에는 read_bundle이 전체 4,451패턴의 피크 samples/플레이북/테마까지 깊은 복사하고, API가 모든 패턴의 실패 설명을 재작성한 후 50개 요약을 잘랐다. 새 listing_view는 캐시에서 필요한 열만 복사하며 전체·상세 조회는 기존 경로를 유지한다. 설명 문구 보정은 실제 반환 페이지(기본 30개)에만 적용한다. 실패 원인 미확인 정책을 제거한 것이 아니다.

모든 반환 중첩 객체를 복사하므로 호출자가 응답을 수정해도 공통 캐시가 변하지 않는다. 필터용 common_event_cluster 및 설명 반복 검사에 필요한 event_hypothesis/mode도 보존했다. 기존 캐시의 failed_years fallback도 유지했다.

## 검사

- 관련 회귀검사 **71 passed / 3.07초**. 신규 projection 검사 5개(매개변수 포함 실행 6개). 캐시 격리, 불필요한 큰 객체 복사 금지, 설명 페이지 5개만 보정, 레거시 관측 fallback 검사.
- 최초 검사에서 기존 read_bundle mock이 새 keyword를 받지 못해 1 fail. 기본 full 경로는 기존 호출 형태를 유지하도록 수정 후 재검사 통과.
- 동일 전체 저장본 필터 결과 1,428개, 요약 29페이지를 기존 full 경로와 비교. 요약/설명 첫 페이지 필드 및 정렬 동일. FastAPI TestClient의 실제 라우트와 이전 세대 409 응답 검사.
- 새 저장본: 기본5년 `46dd0848c8f086c8960d94c07bf0108c0a8500b0d9d392ae5386351edcf83ea9`, 전체 `b55c3098737b53d90ab78c7cbcf5ea2acdcf9537ad7a1ff3d0bce22f0d5a9551`.
- 원천 데이터·현재 점수·선정 규칙·포트폴리오 변경 없음. 공개 사이트 배포, GitHub push, 수집 API 호출 없음.

## 측정 제한 및 운영 적용

web-perf 스킬이 요구한 Chrome DevTools MCP의 navigate_page/performance_start_trace 도구가 없어 해당 정밀 추적 흐름은 중단했다. 서버 코드/함수·TestClient 대체 검사만 수행했다. 브라우저 지표나 전 메뉴 시각 QA 통과라고 주장하지 않는다.

실행 중인 8790 서버는 재시작하지 않았다. 새 조회 저장본은 준비했지만 **새 API 코드 적용에는 서버 재시작이 필요하다.** 현재 진행 중인 사용자 작업을 확인하지 않고 프로세스를 종료하지 않았다.

다음: 서버의 실행 중 작업을 확인한 뒤 재시작/실제 HTTP 확인, 다른 무거운 메뉴·가격 전용 갱신 경로 점검. 공개 정적 파일 전송량 및 전체/상세 최초 JSON 파싱은 이번 범위 밖이다. 이후 메뉴 일치·장애 복구 통합 검사. 역사 원천 확보 및 전체 OOS는 별도 데이터 의존 과제다.
