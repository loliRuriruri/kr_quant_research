# KR Quant Research 신뢰성 감사 및 1차 개선

작성: 2026-09-07 / 기준 커밋: `bd09ece`

## 결론

화면 속도 개선은 일부 확인되었지만, 기존 문서의 '고성능·완성' 주장을 그대로 승인할 수 없다. 특히 모멘텀 화면에 고정 동조율과 만들어진 과거 곡선·승률이 실측처럼 들어 있었고, Quant 비교집단에도 오류가 있었다. 이번 패치는 기능 확대보다 이 허위 확신과 데이터 손상 경로를 제거하는 1차 개선이다.

**수익 예측력 검증 완료, 기관급, 무결점, 완성도 100%를 뜻하지 않는다.** 서버 재시작·전체 엔진 재계산·실제 데이터 E2E·공개 재배포는 별도 확인이 필요하다. 이번 작업에서 운영 서버를 재시작하거나 공개 배포하지 않았다.

## 2. Quant 수정 영향: 실제 저장자료의 제한적 재생

`scripts/audit_peer_replay.py`는 2026-09-04 기준 `latest_all_stocks.parquet` 2,765종목을 읽고, 저장된 peer_n이 있는 유효 지표만 동일하게 구성하여 `bd09ece`와 수정 함수를 비교한다. 네트워크·산출물 변경 없음.

- 가중 점수 차이가 생긴 종목: **532개**
- 가중 차이의 최대 절댓값: **10.7412점**
- 예: ROIC 비교 점수 260개, ROE 213개, FCF 수익률 282개 관측값 변경.
- 네 종목 회귀 예시: 업종 A의 1·2·3, 업종 B의 4가 같은 섹터일 때 B는 기존 '표본 없음/50점'에서 전체 섹터 4종목 기준 100점으로 수정. A의 업종 내 점수는 유지.

이는 **전체 파이프라인의 새로운 최종 순위가 아니다.** 기존 비교 참여가 확인된 표본만 사용하고, 커버리지/적격성/패널티를 새로 산출하지 않은 민감도 진단이다. TOP20 편입·편출과 전체 재무 PIT 검증은 격리된 전체 재계산에서 확인해야 한다. 가중치 30/25/25/10/10 자체는 변경하지 않았다.

## 3. 속도·메뉴 연동 검증

Playwright로 실제 Chromium을 조작했다. 서버는 `tests/e2e/harness.py`의 고정 응답 서버로 운영 포트폴리오·외부 수집과 분리했다.

14개 메뉴 순회에서 클릭→두 번의 animation frame 측정(ms):

| 메뉴 | 시간 | 메뉴 | 시간 |
|---|---:|---|---:|
| 대시보드 | 114 | 점수 랭킹 | 150 |
| 전략·백테스트 | 150 | 테마 | 67 |
| 매크로 | 69 | 업종·섹터 | 81 |
| 메이저 수급 | 104 | 스마트 수급 | 113 |

| 13F | 70 | 은하퀀트 | 63 |
| 실행 파이프라인 | 66 | API 설정 | 101 |

범위 63~150ms. 오류 콘솔 0, 경고 0(비밀번호 form 관련 verbose 메시지는 존재). 이 값은 **UI 전환 반응 시간**이며 실데이터 API 완료시간·최초 데이터 계산시간·배포 사이트 성능이 아니다. 수정 전 같은 조건의 브라우저 기준 측정은 없어 '몇 % 빨라졌다'고 주장하지 않는다. 기존 문서의 2,840→38ms 등 수치는 독립적으로 입증하지 못했다.

기존 E2E가 확인하는 범위: 대시보드 TOP30, 대시보드 Top3↔계절성 순서, 현대차 이름/코드 자동완성, 종목 드로어 외부 링크, 특수 이벤트의 월 필터 독립성, 스마트 수급 탭/기술 필터, 수급 상세 툴팁 등. 고정 응답의 메뉴 연결 검증이지 전 메뉴 실데이터 의미 검증은 아니다. 빈 fixture 응답을 반환하는 일부 메뉴의 내용 완성도는 미검증이다.

스크린샷: `output/playwright/seasonality-audit.png`(대시보드), `output/playwright/seasonality-audit-final.png`(계절성). 테스트용 테마 데이터는 비어 있어 테마맵 실데이터 정상성을 이 이미지로 증명할 수 없다.

## 6. 남은 우선과제 / 완료 조건

1. **격리된 전체 Quant 재계산**: 같은 source bundle·cutoff·설정으로 구/신 엔진 실행. TOP20/100 교집합, 편입·편출 사유, 커버리지·peer_n·패널티 변화 보관. 공개 산출물 덮어쓰기는 승인된 배포 경로만 사용.
2. **계절성 진짜 OOS**: 연도별 학습으로 피크일/테마/월/임계값을 고정한 후 다음 연도만 평가. 중복 이벤트, 최적 월 선택, 다중검정, 시장 대비 초과수익과 비용 포함. 사후 최고점 수익은 예측력 지표로 사용하지 않음.
3. **상폐·정지·기업행위 이력**: 과거 시점 유니버스와 공식 액면분할/권리락/배당/합병 데이터의 커버리지 증거 확보. 35% 점프 필터는 보조 검사이며 공식 기업행위 처리를 대신하지 못함. 월 경계 검사는 휴장일 전체 일치 검증이 아님.
4. **시세의 장중/마감 계약**: KST 타임스탬프, 거래소 세션, 정지·지연 여부, 청산 시 체결가/수수료/세금 구분. 청산 완료 플래그만으로 실현손익을 계산하면 안 됨. 현재 표시는 가격 관측 수익률.
5. **실데이터 메뉴 E2E/지연 계측**: 운영 데이터 복제본에서 첫 클릭·재방문·강제 갱신을 분리하여 API p50/p95와 로딩 완료를 기록. 느린 원천 호출·대량 JSON 파싱·차트 렌더링을 각각 측정. 현재 fixture 수치와 혼동 금지.
6. **저장/캐시 다음 단계**: 현 잠금은 한 프로세스 내 보호다. 다중 worker/별도 프로그램 동시 쓰기에는 파일 잠금 또는 SQLite 트랜잭션 필요. 캐시 항목 수 상한은 있지만 총 바이트 상한은 없음. 원천별 무효화 목록 확장·에러 시 UI 일관성·과거 곡선 provenance 자동 생성도 필요.
7. **설명 신뢰성 전수 감사**: 나머지 화면의 고정 예시, '검증', '정상', '보유', '성공 확률' 표현을 실제 근거 계약과 연결. 이번에 모든 문구를 확인/수정한 것은 아님.

## 7. 실행·복구 주의

이번 변경은 작업트리에 있다. 운영 Python 프로세스는 재시작해야 새 백엔드 코드를 읽는다. 프런트 리소스 버전은 `2.78.9`로 올렸다. 기존 순위 스냅샷은 새 점수로 재계산하지 않았으므로 서버 재시작만으로 순위가 갱신되지는 않는다.

이전 기준은 `bd09ece`이다. 복구 시 코드 패치만 선택적으로 되돌리고, 사용자의 포트폴리오 JSON·.env·시장 데이터는 보존한다. 전체 디렉터리 삭제나 `git reset --hard`로 복구하지 않는다. 기존 캐시는 새 스키마로 분리되며 최초 계절성 조회는 재구축 때문에 평소보다 느릴 수 있다.
