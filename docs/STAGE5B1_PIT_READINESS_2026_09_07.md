# 5B-1: 실제 선취매 과거 입력 준비 상태

## 결과

실제 선취매 전체 전략의 과거 재현은 **NOT_READY**다. 이번에는 저장 원천 7종을 읽는 진단 코드와 미래 정보 유입을 차단할 입력 계약을 추가했다. 운영 선정기 연결, 과거 재계산, 성과 인증은 아직 아니다. 작업 전 롤백 기준은 `16a819e`.

재개·데이터 품질 스킬에 따라 원천 관측과 인증을 분리했다. 현재 값 대입이나 API 수집으로 빈 기간을 숨기지 않았다. 현재 점수·순위·원천·포트폴리오를 변경하지 않았고 운영 서버 재시작, GitHub push, 공개 배포도 하지 않았다.

## 실제 저장 자료

- 가격: 6,106,956행, 3,246종목, 2016-06-17~2026-09-04의 고유 거래일 2,507개. `adj_close`의 Arrow 타입이 null이므로 이 열은 전부 결측이다. 다른 경로의 가격 보정 여부 전체를 검증했다는 의미는 아니다.
- 거래상태 CSV: 13,826행, 2,768종목, 2026-08-28~09-04 중 5개 기준일. 과거 수년간 정지/관리 이력으로 대체할 수 없다.
- 점수 `daily_history`: 99,633행, 2,811종목, 2024-12-30~2026-09-04 중 기준일 13개. 시작/종료일 사이를 매일 보유했다는 뜻이 아니다. 재구성 실행 기록도 포함할 수 있어 당시 관측 장부로 인증하지 않는다. created_at은 시간대 없는 timestamp이므로 UTC 프로파일 표시를 실제 UTC 생성시각으로 해석하면 안 된다.
- 최신 유니버스: 2,765종목, 2026-09-04 단일 기준일. 다른 날짜 폴더 전체의 역사적 완전성은 이번 범위 밖이다.
- 상장 이력: 2,771행, LIST 2,768건·DELIST 3건. 전체 역사적 상장폐지를 확보했다는 근거는 없다.
- 재무: 676,764행, 2,541종목, 기간말 2022-03-31~2026-06-30, 이용가능일 2022-06-09~2026-09-02. 접수번호 결측 0행, 이용가능일=기간말 0행. 따라서 `ingest/live.py`의 접수번호 미확보 시 기간말 fallback이 이 자료에 발생했다고 단정하지 않는다.
- 다만 재무 revision_id=1, is_correction=false, is_withdrawn=false가 전 행에 동일하다. 수집 코드가 상수로 기록하므로 정정·철회가 없었다는 증거가 아니다. 공시 원문 버전과 공개시각을 대조해야 한다.
- 7종 모두 지정 후보 키의 중복·결측 행은 0이고 읽기 전후 SHA-256은 동일했다. 이는 지정 키·해당 파일 검사 결과이며 내용의 정확성이나 여러 파일의 동일 세대 일치 인증은 아니다.

원본 감사 JSON: `output/audit/pit-readiness-20260907.json` (로컬 Git 제외). 결과 해시 `893b6f110d0116449a8e999295fb837122cffe81579b861a9e21f6092c454cb9`.

## 코드와 합격 경계

`research/pit_readiness.py`:

- 선택한 운영 파일의 Arrow 스키마·행수·종목수·날짜 분포·후보 키·재무 접수번호/버전 상태를 점검한다.
- 파일 부재, 읽기 오류, 읽는 중 변경을 구분한다. 구조상 정상이어도 historical_availability=UNVERIFIED를 유지한다.
- `validate_replay_inputs`는 명시적 시간대가 있는 판단시각, 입력 파티션 ID, 원래 이용 가능 시각, 사용한 최신 관측시각, 해시 형식, 출처 참조를 요구한다.
- 미래 이용 가능 시각/관측, 중복, 필수 입력 누락을 BLOCKED 처리한다. 정상은 **CONTRACT_VALID / verified=false**다. 파일 해시의 실제 대조나 공시 진실성을 이 함수가 인증하지 않는다.
- 이 검사는 향후 과거 재현 진입점에 연결할 사전 검사다. 현재 운영 UI·선정 파이프라인을 차단하지 않는다.

CLI는 출력 경로가 존재하면 거절하고 새로운 불변 감사 결과만 작성한다. 수집 API, 키 발급, 데이터 캐시 생성, 서버 동작 변경 없음.

## 검증 및 산출물 한계

최초 새 단위검사 12 passed. 기존 관련 회귀검사 포함 61 passed / 9.78초. 이후 빈 필수계약 및 읽는 중 변경 검사 2개를 추가해 최종 **63 passed / 3.89초**(새 검사 14개)를 확인했다. 전체 저장소 테스트 또는 투자 성과 검증이 아니다.

동반 노트북 `docs/audits/pit-readiness-20260907/pit-readiness.ipynb`: 코드셀 3개 순차 실행 성공. nbformat/nbclient/ipykernel이 없어 정식 Jupyter 실행·구조 검증은 미수행. JSON 파싱과 코드셀 실행만 확인했다. 의존성이 있는 환경에서는 다음으로 재검증한다.

```powershell
.\.venv\Scripts\python.exe -m jupyter nbconvert --execute --to notebook --inplace docs/audits/pit-readiness-20260907/pit-readiness.ipynb
```

기술 보고서 canonical `artifact.json`은 검증 통과. HTML 패키징은 2회 모두 desktop 1440px 가로 넘침 검사에서 실패해 **완성 HTML 보고서를 전달하지 않는다**. 실패 이미지는 같은 폴더에 로컬 진단으로만 보관하고 커밋에서 제외한다. 별도 HTML 렌더러를 만들거나 검사를 끄지 않았다. 이 문서와 노트북이 읽을 수 있는 인계 자료다.

보고서 차트 계약: 동일 날짜 개수 지표를 가진 저장본 3개(점수/상태/최신 유니버스)의 막대 비교, 0 기준·단색·직접 수치. 원천 가격일/공시일/상장일은 의미가 달라 비교에서 제외했다. 개수가 세 범주뿐인 것은 확인된 기준일 자료만 비교하기 위함이며 기간별 추세·완성도 비교가 아니다. 기술 보고서의 범위/정의는 수치 해석보다 앞에 배치했다. 데이터 품질·노트북·보고서 스킬이 근거와 산출물 검증 경계를 명시하도록 했다.

## 다음 순서와 남은 범위

### 5B-2: 시점 분리와 입력 어댑터

1. `pattern_from_month_stat`의 현재 연도 참조와 미완료 월 차단을 명시적 시점으로 분리한다. 날짜 없는 레거시 배열을 과거 연도에 임의 배정하지 않는다.
2. 최신 점수·현재 적격 종목·최근 수급 fallback을 제거한 별도 과거 입력 경로를 만들고 생산 순위 함수를 공유한다. 현재 화면 결과 보존과 미래 데이터 변경 불변성 테스트를 함께 수행한다.
3. event_confidence는 계절성 점수에 들어가므로 당시 지식 버전이 없는 경우 별도 연구 모델로 구분한다. 원래 모델과 같다고 표시하지 않는다.

### 5B-3: 확보 구간 재현·성과

거래상태/정정 공시/상폐/기업행위 증거가 있는 구간부터 선정·제외 장부를 고정한다. 미확보 구간은 실패/미검증 분모에 남긴다. 실제 체결 시점·비용·공식 거래일과 다중 탐색 편향 검사를 붙이고, 현재부터 쌓는 실측 장부와 재구성 성과를 구분한다.
