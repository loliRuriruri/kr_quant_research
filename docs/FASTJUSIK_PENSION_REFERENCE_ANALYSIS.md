## 기술 요약

가장 가치가 큰 부분은 색상이나 장식이 아니라 **연기금 수급을 하나의 탐색 흐름으로 묶은 정보 구조**다. 사용자는 시장 전체 요약에서 시작해 연속 매집, 당일 순위, 외국인 동반, 방향 전환, 기간 누적을 비교하고, 종목을 누르면 90거래일 수급과 개인·외국인·기관 누적 차트로 내려간다.

우리 앱에는 이 흐름을 다음과 같이 반영하는 것이 좋다.

1. `수급 분석` 페이지를 새로 만들고 연기금·외국인 데이터를 공통 데이터 모델로 저장한다.
2. 종목 상세에 `가격 + 연기금 + 외국인 + 기관 + 개인`을 한 화면에서 비교하는 수급 탭을 추가한다.
3. 시장 국면에 경제 캘린더와 CPI·PCE·미 10년물·USD/KRW·VIX·KOSPI 탭을 추가한다.
4. OpenDART 대량보유 상황보고를 이용해 국민연금 5% 이상 보유 종목과 지분 변화를 관리한다.
5. 숫자 나열보다 먼저 “무엇이 바뀌었는지”를 설명하는 일일 수급 브리핑을 생성한다.

**그대로 가져오지 않을 것:** FASTJUSIK의 HTML/CSS/JS 원문, 로고·브랜드 문구, 공개 API에 대한 운영 의존, 장중 연기금 추정치, 해외 파생상품을 국내 종목의 야간 추정가로 환산하는 기능, 채팅·자동매매 홍보 요소다. 화면 설계 원칙과 계산 아이디어만 재구현한다.

## 가져올 UX 패턴

### 1. 결과부터 보여주는 상단 요약

원본은 상단에서 당일 순매수·순매도 총액, 상위 10종목, 경제 일정, 브리핑을 먼저 제시한다. 긴 표를 읽기 전에 오늘의 방향을 파악하게 만드는 구조다.

우리 앱의 상단은 다음 5개 지표가 적합하다.

- 연기금 시장 전체 순매수 금액
- 전일 대비 순매수 변화
- 연속 순매수 종목 수 / 연속 순매도 종목 수
- 연기금·외국인 동반 매수 종목 수
- 5거래일 이상 흐름 뒤 방향 전환 종목 수

그 아래에는 규칙 기반 한 문단을 먼저 표시한다. AI가 실패해도 기본 문장은 항상 생성돼야 한다.

### 2. 여덟 개 분석 모드를 2행 탭으로 구성

원본은 `연속 수급 / 외국인 동반 / 연기금 당일 / 외국인 당일 / 기간 누적 / 시장 요약 / 경제지표 / 보유 포트폴리오`를 4열 2행으로 배치한다. 페이지를 여러 메뉴로 흩뜨리지 않고 같은 문맥에서 전환할 수 있다는 점이 좋다.

Streamlit에서는 상단에 `st.segmented_control`을 두 개 놓거나, 4열 버튼 2행 + `session_state`로 활성 탭을 관리한다. 탭 전환 때 전체 페이지를 다시 탐색하게 하지 말고 선택 종목·기간·시장 필터를 유지한다.

### 3. 매수·매도 양쪽을 동시에 비교

데스크톱은 순매수와 순매도를 좌우 2열로 보여주고, 모바일은 `순매수 / 순매도` 전환 버튼으로 한 표만 보여준다. 이는 작은 화면에서 가로 스크롤을 피하는 좋은 패턴이다.

- 900px 이상: 2열 비교
- 560px 이하: 단일 표 + 방향 전환
- 390px 화면에서도 종목명, 연속일, 누적금액이 잘리지 않아야 함

### 4. 금액 셀 안의 상대 크기 막대

원본은 순매수 1위 대비 상대 크기를 셀 배경 그라데이션으로 표시한다. 숫자를 읽지 않아도 집중도를 파악할 수 있다.

우리 구현에서는 `abs(value) / max(abs(value))`를 0~1로 정규화해 데이터바를 그린다. 색상은 국내 시장 관례에 맞춰 상승·매수는 빨강, 하락·매도는 파랑을 사용하되 색상만으로 의미를 전달하지 않고 `+/-`, `매수/매도` 텍스트를 함께 둔다.

### 5. 종목 행 전체를 상세 진입점으로 사용

표의 종목 행을 누르면 상세 차트로 이동한다. 우리 앱도 종목명에 작은 링크만 두기보다 행 선택을 감지해 `종목 상세`의 해당 종목·수급 탭을 연다. 기존 네이버·토스 외부 링크는 보조 동작으로 유지한다.

## 종목 상세에서 가져올 구조

원본의 삼성전자 상세 화면은 다음 순서를 사용한다.

1. 최근 확정 순매수, 현재 연속 방향, 60거래일 누적, 기록 거래일 KPI
2. 최근 90거래일 연기금 순매수 양·음 막대
3. 주가와 개인·외국인·기관 누적 순매수 선 그래프
4. `1개월 / 3개월 / 전체`, `누적 / 당일` 전환
5. 최근 거래 내역 표

![원본 종목 상세 화면](research/fastjusik.com/screenshots/pension-stock-detail.png)

우리 앱에는 아래 차트를 추가한다.

- **연기금 순매수 막대:** 0선을 중심으로 양수/음수 막대
- **가격 + 투자자 수급:** 가격은 별도 축 또는 위 패널, 투자자 누적은 아래 패널
- **수급 괴리:** 가격 수익률 z-score와 투자자 누적 순매수 z-score의 차이
- **집중도:** 당일 연기금 순매수 금액 / 당일 거래대금
- **지속성:** 현재 방향 연속일, 최근 20일 양의 순매수 일수 비율

종목 설명은 “매수 추천”이 아니라 다음 형태로 제한한다.

> 최근 20거래일 중 14일 연기금 순매수가 발생했고 누적 420억원입니다. 주가는 같은 기간 3.2% 상승했습니다. 연기금과 외국인이 3거래일 연속 같은 방향이지만, 오늘 순매수 강도는 20일 중앙값보다 낮습니다.

### 새 수집이 필요한 것

| 기능 | 권장 공식 소스 | 필요한 작업 |
|---|---|---|
| 종목별 개인·외국인·기관·기금 일별 수급 | KIS `investor_trade_by_stock_daily` | 어댑터·필드 매핑·호출 제한 관리 |
| 당일 투자자 동향 | KIS `inquire-investor` | 장 종료 후 확정 시점 저장 |
| 연기금 세부 분리 | 소스가 제공하는 투자자 구분 명세 확인 | KIS의 `fund_*`는 우선 `기금` 원천값으로 보관하고, 연기금과 동일한지 명세·표본으로 검증 |
| 국민연금 5% 이상 보유 | OpenDART `majorstock.json` + 공시검색 | 제출인명 필터·정정공시 처리 |
| VIX·미 10년물·CPI·PCE | FRED 공식 시계열 | series 설정과 available date 저장 |
| 경제 캘린더 예상/실제 | 공식 발표기관 또는 허가된 캘린더 제공자 | FRED만으로 예상치 캘린더는 부족 |
| SEC 13F 해외 보유 | SEC EDGAR 공식 데이터 | CIK·분기·수정 제출 관리 |

현재 승인된 KRX 4개 엔드포인트는 종가·OHLCV·거래대금·시총·종목기본정보만 제공한다. **이 데이터만으로 연기금 또는 외국인 순매수를 역산할 수 없다.** KIS의 공식 투자자 동향 API를 우선 연결해야 한다.

다만 현재 KIS 어댑터는 일별 가격과 종목 마스터만 구현돼 있다. 또한 KIS의 종목별 투자자 일별 API는 종목 단위 호출이므로 전 종목·장기 이력 일괄 적재에 호출 제한 문제가 생길 수 있다. P0에서는 상위 유동성 종목과 관심종목으로 필드·제한을 검증하고, 전체 시장 랭킹에는 **하루 한 번 전 종목을 반환하는 공식 원천**을 확보한 뒤 확대한다. 해당 원천을 찾기 전에는 전 종목 연기금 순위를 제공한다고 주장하지 않는다.

## 제안 데이터 모델

### `investor_flows_daily`

| 컬럼 | 설명 |
|---|---|
| `date` | 거래일 |
| `ticker` | 종목코드 |
| `investor_type` | `FUND`, `FOREIGN`, `INSTITUTION_TOTAL`, `INDIVIDUAL` 등 원천 명세 기반 분류 |
| `buy_value` / `sell_value` | 매수·매도 금액 |
| `net_value` | 순매수 금액 |
| `buy_qty` / `sell_qty` | 매수·매도 수량 |
| `net_qty` | 순매수 수량 |
| `is_final` | 확정 여부 |
| `source` | 공식 소스 |
| `fetched_at` / `run_id` | 수집 추적 정보 |

기본키는 `(date, ticker, investor_type, source)`로 둔다.

`PENSION`은 원천이 명시적으로 “연기금”을 제공할 때만 별도 분류로 사용한다. `FUND`를 국민연금 단독 또는 공적연금 합계로 이름만 바꾸면 안 된다.

### `ownership_positions`

| 컬럼 | 설명 |
|---|---|
| `report_date` | 공시 기준일 |
| `ticker` | 종목코드 |
| `holder_name` | 보고자명 |
| `holding_ratio` | 지분율 |
| `previous_ratio` | 직전 지분율 |
| `share_count` | 보유주식수 |
| `receipt_no` | DART/SEC 접수번호 |
| `available_date` | 시스템에서 사용 가능한 최초 날짜 |
| `source` | DART 또는 SEC |

### `economic_calendar`

발표일시, 국가, 지표명, 중요도, 이전·예상·실제, 단위, 수정 여부, 출처를 저장한다. 발표 이전에는 `actual`을 비워 두고 발표 후 갱신한다.

## 파생 지표 계산 규칙

원본 화면에서 확인한 의미를 우리 데이터 모델에 맞춰 독립적으로 정의한다.

### 연속 수급

1. 종목·투자자별로 날짜 오름차순 정렬한다.
2. `net_value > 0`은 매수, `< 0`은 매도, `= 0`은 중립으로 분류한다.
3. 최신 거래일부터 같은 방향이 이어진 길이를 센다.
4. 누적금액은 해당 연속 구간의 `net_value` 합계다.
5. 데이터 시작일에 닿은 경우 `capped=true`로 표시해 실제 연속 기간이 더 길 수 있음을 알린다.

### 동반 매매

같은 날짜·종목에서 연기금과 외국인의 `net_value` 부호가 같을 때만 포함한다. 정렬값은 기본적으로 `abs(pension_net) + abs(foreign_net)`이며, 개별 금액을 함께 보여준다.

### 방향 전환

직전까지 `N`거래일 이상 같은 방향이었고 오늘 부호가 반대인 종목이다. 기본 `N=5`, 화면에서 3·5·10일을 선택할 수 있게 한다. 0원 또는 극소액 반전은 노이즈이므로 `abs(net_value) / trading_value` 최소 임계값을 추가한다.

### 기간 누적

5·20·60거래일과 전체 기간을 기본으로 제공한다. 달력일이 아니라 거래일 기준을 사용한다.

### 수급 강도

`net_value / trading_value * 100`으로 계산한다. 대형주와 소형주의 금액 규모 차이를 보정하기 위해 순매수 금액 순위와 수급 강도 순위를 분리한다.

## 일일 브리핑 설계

브리핑은 다음 순서로 생성한다.

1. 시장 전체 연기금 순매수/순매도 및 최근 20일 내 위치
2. 당일 상위 매수·매도 종목과 금액
3. 5일 이상 연속 수급 종목
4. 연기금·외국인 동반 종목
5. 방향 전환과 이례적 수급 강도
6. 데이터 확정 여부·결측·지연 경고

규칙 기반 요약을 먼저 만들고 AI는 문장 정리와 상충 신호 해석만 담당한다. AI가 숫자를 새로 계산하거나 존재하지 않는 원인을 단정하지 못하게 한다. 모든 숫자는 입력 JSON에서 그대로 가져오며 DART 근거가 있는 보유 변화는 접수번호를 함께 저장한다.

## 시장 국면 화면과의 결합

원본 경제지표 탭은 `미국 CPI / 미국 PCE / 미 10년물 / 원·달러 / VIX / 코스피`를 같은 위치에서 전환한다. 이 구조는 현재 시장 국면 페이지에 잘 맞는다.

권장 구성은 다음과 같다.

- 상단: 현재 시장 국면, 전일 변화, 위험회피 경계까지 거리
- 중단: 기존 7개 국면 구성요소
- 하단 탭: KOSPI, VIX, 미 10년물, 10Y-2Y, USD/KRW, CPI, PCE
- 각 차트 아래: 최신값·20일 변화·1년 백분위·시장 해석
- 가장 아래: 연기금 시장 전체 순매수 추이와 국면 점수의 동시 표시

VIX는 현재 `volatility_score`와 다른 값이다. 기존 변동성 점수는 KRX 종목 수익률 변동성을 반전한 안정 점수이므로 화면과 DB에서 혼용하면 안 된다.

## 완료 기준

- 연기금·외국인·기관·개인 데이터가 투자자 유형별로 혼동 없이 저장된다.
- 화면의 모든 금액에 기준일, 단위, 확정 여부가 표시된다.
- 기간 계산은 달력일이 아닌 거래일을 사용한다.
- 데스크톱과 390px 모바일에서 표가 잘리거나 가로 스크롤을 강요하지 않는다.
- 종목 검색과 행 클릭이 마우스·키보드 모두 동작한다.
- 연속 수급·동반 수급·방향 전환 계산에 단위 테스트가 있다.
- AI가 실패해도 규칙 기반 설명과 차트는 정상 표시된다.
- 가격 데이터만 있는 경우 연기금 값을 추정하거나 가짜 데이터로 채우지 않는다.
- 외부 사이트 API 중단이 우리 앱 장애로 이어지지 않는다.

## 제한과 법적·운영 경계

- 이 문서는 공개 화면과 공개 네트워크 응답의 구조를 분석한 것이다.
- FASTJUSIK의 브랜드, 문구, 로고, HTML/CSS/JS 원문과 데이터셋을 재배포하지 않는다.
- 공개 엔드포인트가 인증 없이 응답하더라도 이를 생산 시스템의 무단 데이터 공급원으로 사용하지 않는다.
- 동일 기능은 KRX·KIS·OpenDART·FRED·SEC 등 사용 권한이 명확한 원천에서 다시 수집하고 독립적으로 계산한다.
- 원본도 수급 데이터 출처를 KRX 통계정보와 DART로 명시하며, 시세 지연·오류 가능성과 투자 참고용임을 고지한다.
