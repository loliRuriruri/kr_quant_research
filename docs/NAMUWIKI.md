## 1. 개요

**KR Quant Research**는 대한민국 유가증권시장(KOSPI)과 코스닥(KOSDAQ) 상장 종목 전체를 대상으로 재무제표와 주가를 분석하여 **매일 동일한 수학 공식으로 유망 종목을 선별·스코어링하는 정량 리서치 시스템**이다.

흔해 빠진 주식 리딩방이나 매수/매도 시그널 생성 봇이 **절대 아니다.** 순수하게 투자자가 2,700여 개 한국 주식 중에서 좋은 기업을 찾아내고, 기관/외인의 자금 흐름과 매크로 환경, 계절성 이상현상을 교차 검증할 수 있도록 돕는 **조사(Discovery & Research) 전용 무기**에 가깝다.

로컬 PC에서 강력한 백엔드(FastAPI + DuckDB)로 무거운 데이터 연산과 AI 심층 분석을 돌리고, 외부에서 조회할 수 있도록 Cloudflare Pages에 정적 JSON 스냅샷을 배포하는 **철저한 이원화 아키텍처**를 채택하고 있다.

## 2. 개발 철학과 절대 깨지지 않는 6대 원칙

이 프로젝트의 코드베이스 곳곳에는 주석과 규칙으로 엄격한 제약이 걸려 있다. 문서 편집자들의 증언에 따르면, AI 코딩 에이전트들이 편리함을 핑계로 이 제약을 깨려 할 때마다 수많은 커밋이 리버트(Revert)당했다고 전해진다.

### 2.1. 자동매매 기능의 원천 배제 (~~한강 방지턱~~)
* **주문·잔고·체결 API는 코드에 1줄도 넣지 않는다.**
* 한국투자증권(KIS)이나 키움증권 키가 `.env`에 등록되어 있어도, 오직 시세 조회와 투자자별 수급 조회(READ-ONLY)로만 사용된다. 주문 엔드포인트를 호출하는 함수는 아예 작성 자체를 금지하고 있다. 개발자의 돈과 정신 건강을 지키기 위한 최후의 물리적 안전장치다.

### 2.2. 퀀트 점수의 완전한 결정론 (AI 개입 절대 금지)
* 퀀트 점수는 가치 30, 품질 25, 성장 25, 모멘텀 10, 재무안정 10의 100점 만점으로 계산된다.
* **LLM(인공지능)이 점수나 팩터 가중치, 순위를 수정하는 행위는 사형감이다.** AI는 오직 계산된 팩트 데이터를 바탕으로 해설 리포트를 작성하거나 맥락을 브리핑하는 '설명자' 역할에 머문다.

### 2.3. 레이어의 엄격한 분리 (Overlay 미합산)
* 메이저 수급(외인/기관/사모), 글로벌 거시 매크로, 미국 SEC 13F 지분, 스토캐스틱/일목균형표, 손자병법 오사는 모두 **`used_in_quant: false`** 속성을 갖는다.
* 아무리 외인과 기관이 쌍끌이 매수를 퍼붓거나, 워런 버핏이 매수한 섹터라도 재무 퀀트 점수 자체에는 1점도 가산되지 않는다. 퀀트와 수급/타이밍은 철저히 별개의 렌즈로 바라본다.

### 2.4. 정본 데이터에 대한 집착 (KRX & OpenDART)
* **가격의 정본은 오직 KRX Open API**뿐이다. Yahoo Finance나 네이버 증권 시세는 보조 비교용일 뿐, 퀀트 점수 산출의 정본으로 승격될 수 없다.
* **재무의 정본은 금융감독원 OpenDART TTM(Trailing Twelve Months)**이다. 당기 공시일자 기준(`action_date: NEXT_TRADING_DAY`)만을 엄수하는 완전한 PIT(Point-In-Time)를 적용하며, 한 TTM 구간 내에서 연결재무제표(CFS)와 개별재무제표(OFS)를 섞는 것은 데이터 범죄로 간주된다.

### 2.5. 이원화 아키텍처 (로컬 두뇌 vs 공개 거울)
* **로컬 엔진 (`http://127.0.0.1:8790`)**: API 키를 쥐고 KRX/DART를 수집하며 퀀트를 계산하는 본체.
* **공개 웹 (`korea-quant-research.pages.dev`)**: 계산된 최종 결과물에서 API 키, 개인 로그, 원문 응답을 완벽히 탈곡한 정적 JSON 스냅샷. PC가 꺼져 있어도 스마트폰으로 대시보드를 열람할 수 있다.

### 2.6. 비밀번호와 API 키의 봉인 (.env 엄수)
* 모든 시크릿 키는 오직 로컬 `.env`에만 존재한다. 코드, 로그 파일, AI 프롬프트, JSON 출력, Git 커밋에 단 하나의 키라도 유출되는 순간 빌드 파이프라인에서 에러를 뿜으며 즉각 배포를 중단한다.

## 3. 개발 역사와 개발 비화

### 3.1. 제1기: 스크리너와 디스커버리의 결합
원래 이 프로젝트는 두 개의 서로 다른 레거시 프로그램에서 출발했다.
1. `stock_screener` (포트 8787): DART 재무제표를 긁어와 DuckDB에 넣고 재무 팩터를 매기던 순수 재무 계산기.
2. `korea-quant-discovery-engine` (포트 8501, Streamlit): 시장 국면과 테마, 수급을 시각화하던 탐색 도구.

두 프로그램을 단순 무식하게 이어붙이면 괴물이 탄생할 것이 뻔했기에, 개발팀은 역할을 명확히 나누어 **FastAPI 백엔드 + 바닐라 JS 단일 페이지 대시보드**로 처음부터 다시 설계했다.

### 3.2. 제2기: 모멘텀과 상장주식수 보정 논쟁
초기 아키텍처 문서에는 "모멘텀 팩터 미사용(disabled)"으로 기록되어 있었다. KRX 공식 API가 배당 재투자(TR) 수정주가를 제공하지 않았기 때문. 

하지만 액면분할이나 무상증자로 주가가 하루아침에 1/10 토막 난 기업이 모멘텀 -90%로 찍혀 저평가 우량주에서 탈락하는 참사가 벌어지자, **"상장주식수와 시가총액을 역산하여 액면분할만을 보정하는 모멘텀 엔진(`listed_shares_adjustment: true`)"**을 자체 개발하여 10점 배점으로 부활시켰다. (배당 TR은 여전히 미반영인데, 스크리너 목적상 불필요한 노이즈를 줄이기 위한 의도적 선택이다.)

### 3.3. 제3기: 알파AI(043100) 사태와 5중 리스크 가드레일
어느 날, 과거 데이터 상으로 완벽한 재무제표를 자랑하던 종목 하나가 퀀트 상위권에 당당히 랭크되었다. 확인해 보니 장기 거래정지 상태에 상장폐지 실질심사를 받고 있던 **알파AI(043100)**였다.[^1]

이 충격적인 사건 이후 2026년 8월 26일, 전면적인 **5중 리스크 가드레일 대격변**이 단행되었다.
1. **Layer 1 (Active Trading)**: 최근 10영업일 내 실제 체결 내역이 없는 거래정지 종목 100% 원천 배제.
2. **Layer 2 (Penny Stock Guard)**: 주가 1,000원 미만 동전주 차단.
3. **Layer 3 (DART & KRX Risk Filter)**: 관리종목, 투자주의환기종목, 상장폐지 절차 진행 종목 즉시 컷.
4. **Layer 4 (Liquidity Filter)**: 일평균 거래대금 미달, 스팩, 우선주, 리츠 등 비보통주 제외.
5. **Layer 5 (Calendar Year Integrity)**: 과거 정지 기간이 포함된 왜곡 연도 데이터 검증.

이로써 좀비 기업이 퀀트 리더보드에 기어 올라오는 일은 영원히 차단되었다.

### 3.4. 제4기: P0~P2 데이터 무결성 대수술 (2026 하반기)
2026년 8월 말부터 9월 초까지 진행된 신뢰성 하드닝 작업은 시스템을 상용 금융 솔루션 수준으로 끌어올렸다.
* **종목코드 알파벳 증발 버그 해결**: `0220W0`(우선주/전환주)의 문자가 숫자로 잘못 파싱되어 `000220`(유유제약) 수급으로 둔갑하던 버그를 박멸했다.
* **스마트 실행 원장(Ledger)**: 장 마감 후 KRX 시세가 안 떴는데도 "오늘치 수집 완료"로 처리해버리던 멍청한 스케줄러를 갈아엎고, 단계별 재시도 상태머신을 구축했다.
* **백테스트 데이터 누수(Lookahead) 완전 차단**: 마지막 20% OOS(Out-of-Sample) 구간의 수익률이 1위 전략 선정 알고리즘에 개입하지 못하도록 엄격히 격리했다.

## 4. 퀀트 스코어링 시스템 (100점 만점 구조)

퀀트 스코어는 철저히 **상대평가(피어 그룹 백분위)**와 **절대적 재무 건전성**의 결합이다. 업종(KSIC) 표본이 20개 이상이면 업종 내에서, 부족하면 대섹터(40개 이상), 그래도 모자라면 전체 시장을 기준으로 윈저라이징(극단치 보정)을 거친다.

```

                                         |
     +-----------------+-----------------+-----------------+-----------------+
     |                 |                 |                 |                 |
[가치 (Value)]    [품질 (Quality)]  [성장 (Growth)]   [모멘텀 (Momentum)] [안정 (Stability)]
   (30점)            (25점)            (25점)            (10점)            (10점)
   - EV/EBIT (9)     - ROIC (9)        - 매출 YoY (6)    - 6개월 수익 (3)   - 순부채비율 (2)
```

### 4.1. 가치 (Value - 30점)
싼 주식을 찾는다. 단, 이익이 적자이거나 자본잠식인 기업은 지표 자체가 무효화된다.
* **EV/EBIT (9점)**: 영업이익 대비 기업가치. (영업적자 시 무효)
* **FCF Yield (8점)**: 시가총액 대비 잉여현금흐름(FCF).
* **Earnings Yield (7점)**: PER의 역수. (지배주주순이익 적자 시 무효)
* **PBR (6점)**: 주가순자산비율. (자본총계 0 이하 시 무효)

### 4.2. 품질 (Quality - 25점)

* **ROIC (9점)**: 투하자본이익률. 영업활동에 투입된 자산이 낸 실질 수익성.

* **ROE (4점)**: 자기자본이익률.
* **CFO / Net Income (4점)**: 순이익 중 실제 영업현금흐름의 비율 (회계 분식 방어선).
* **8분기 마진 안정성 (3점)**: 영업이익률의 8분기 변동계수.

### 4.3. 성장 (Growth - 25점)
지속적으로 파이를 키워가는지 본다.
* **매출액 YoY TTM (6점)**: 전년 동기 대비 최근 1년 매출 증가율.
* **영업이익 YoY TTM (6점)**: 전년 동기 대비 최근 1년 영업이익 증가율.
* **매출액 3년 CAGR (5점)**: 3개년 연평균 매출 성장률.
* **EPS YoY TTM (4점)**: 주당순이익 성장률.
* **영업이익 3년 CAGR (4점)**: 3개년 연평균 영업이익 성장률.

### 4.4. 모멘텀 (Momentum - 10점)
추세를 탄 종목에 가산점을 준다. (주식수 변동으로 분할 보정 완료)

* **시장 대비 6개월 초과수익률 (2점)**
* **52주 최고가 근접도 (1점)**

### 4.5. 재무안정성 (Stability - 10점)
흑자도산이나 과도한 빚더미를 거른다.
* **순이자부채 / 자산 (2점)** / **부채비율 (2점)** / **이자보상배율 (2점)**
* **영업현금흐름 / 자산 (2점)** / **유동비율 (2점)**

### 4.6. 소프트 페널티 (Soft Risk Penalty - 최대 -15점)

## 6. 데이터 파이프라인과 신뢰성 엔지니어링

### 6.1. 스마트 실행 원장 (Smart Run Ledger)
평일 오후 19시 10분이 되면 백그라운드 스케줄러가 조용히 깨어난다.
* 단순히 스크립트를 맹목적으로 실행하는 것이 아니라, `logs/smart_run_ledger.json` 원장을 확인하여 **KRX 시세가 한국거래소 서버에 올라왔는지부터 확인**한다.
* 시세가 아직 안 올라왔으면 25분 뒤 시세 단계만 최대 6회 재시도한다. 다른 작업이 돌고 있으면 무리하게 중복 실행하지 않고 다음 턴으로 양보한다.

### 6.2. 원자적 파일 교체 (Atomic Parquet Swap)
데이터 수집 중 네트워크가 끊기거나 컴퓨터가 꺼졌을 때, 기존에 잘 돌아가던 Parquet 데이터 파일이 깨지는 것을 방지한다.
* 모든 데이터는 먼저 `temp_xyz.parquet` 임시 파일에 기록되고, 컬럼 구조와 유효 행 수를 완벽히 검증한 뒤에야 OS 파일 시스템 수준의 **원자적 교체(Atomic Replace)**를 통해 본 파일로 교체된다. 실패 시 이전 정상 파일이 100% 보존된다.

### 6.3. 배포 가드레일 (가짜 성공 차단)
로컬 대시보드의 데이터를 Cloudflare Pages 공개 웹으로 업로드할 때 가동되는 보안 게이트다.
* 현재 데이터가 데모 모드이거나, 부분 성공(partial) 상태이거나, 시세 기준일이 오늘 날짜와 불일치하거나, 위험 경고가 남아 있으면 **빌드 자체를 거부**한다.
* 인터넷 세상에 낡았거나 잘못된 주식 정보가 배포되는 것을 시스템적으로 원천 봉쇄한다.

* **주요 대사 톤앤매너**: "양 제독님의 가르침대로 재무 건전성을 먼저 확인했습니다. 5대 팩터 점수가 고르게 우수하므로, 3단계 분할 매수 전략으로 접근하는 것이 합리적입니다."

## 8. 여담 및 트리비아

### 8.1. 왜 React나 Next.js를 안 쓰고 바닐라 JS를 썼는가?
이 거대한 시스템의 프론트엔드는 놀랍게도 프레임워크 없는 **순수 바닐라 자바스크립트(Vanilla JS)**와 CSS3로만 작성되어 있다.  
초기 개발 단계에서 Node.js 빌드 체인 의존성을 최소화하고, 로컬 환경에서 번들링 없이 즉시 브라우저로 0.1초 만에 렌더링하기 위한 선택이었다. 덕분에 React 버전 충돌이나 npm 의존성 지옥에 빠질 일이 전혀 없다.[^3]

### 8.2. KIS 토큰 알림톡 폭탄 사건
개발 도중 한국투자증권(KIS) OAuth 토큰을 발급받는 로직에 사소한 버그가 있었는데, 사용자가 종목 상세창을 클릭할 때마다 매번 새 토큰을 요청하는 바람에 개발자 스마트폰으로 **카카오톡 인증/토큰 발급 알림톡이 1분에 수십 통씩 융단폭격**되는 참사가 일어났다. 현재는 프로세스 메모리와 캐시 파일에 24시간 TTL로 토큰을 단단히 묶어두어 평화를 되찾았다.

### 8.3. "국민연금"이 아니라 "기금"이라고 불러야 하는 슬픈 사연
증권사 수급 데이터(KIS 등)의 기관 분류 항목에는 `FUND`라는 코드가 있다. 많은 주식 초보들이나 허술한 앱들은 이를 보고 무조건 "국민연금이 샀다!"라고 단정 짓는다.  
하지만 금융 데이터 원천 정의상 `FUND`는 우정사업본부, 사학연금, 공무원연금 등 각종 공적 기금이 모두 섞여 있는 통계다. 프로젝트 창립자는 **"원천이 명시하지 않은 것을 우리 멋대로 국민연금으로 개명하는 것은 데이터 사기다"**라는 엄명을 내렸고, 현재 시스템에서는 반드시 검증 전까지 **`기금`**으로 표기하도록 하드코딩되어 있다. (실제 국민연금 데이터는 DART의 5% 대량보유 공시를 직접 긁어오는 별도 엔진에서만 '국민연금'으로 표기된다.)

### 8.4. 바탕화면 CMD 창 숨김 대작전
`Start-KR-Quant.bat`으로 서버를 띄우면 백엔드 파이썬 프로세스 때문에 빈 검은색 CMD 창 하나가 화면에 하루 종일 떠 있는 거슬리는 문제가 있었다.  
`launch.ps1` 내부의 윈도우 프로세스 생성기를 WMI의 `Win32_ProcessStartup`과 `ShowWindow = 0 (SW_HIDE)` 옵션으로 감싸면서, 현재는 완전히 무소음 백그라운드 프로세스로 동작하게 되었다.
