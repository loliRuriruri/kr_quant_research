# 4단계 — 시즌 탐색·설명 목록 경량화

## 결과

시즌 탐색의 전 종목 상세 일괄 전송을 선택적 요약 페이지로 바꿨다. **선정 엔진·점수·순위·원천 데이터는 바꾸지 않았다.** 기존 full API는 호환용으로 유지하며, 새 로컬 화면은 탐색 50개/설명 30개씩 조회한다. 전체 메뉴 또는 실시간 데이터 개선 완료를 의미하지 않는다.

작업 전 저장점: `3fa95dc`. 사용자 `data/calendar_momentum_portfolio.json`의 기존 개행 변경은 보존하고 커밋에서 제외한다.

## 실제 데이터·브라우저 확인

동일 조건: horizon=90, lookback=0(전체), exclude_expired=true.
공통 세대: `88a8ab29b4f7a322d072025ead5759fbd012671a9947ceb37321904d0e6c77a9`.

| 응답 | JSON 크기(압축 해제) | 내려받은 후보 | 브라우저 요청 관측 |
|---|---:|---:|---:|
| 기존 full | 10,960,520 byte | 1,428 | 이전 단계 약 1,808ms |
| 탐색 첫 페이지 | 66,903 byte | 50 | 528ms / 전송 10,216 byte |
| 설명 첫 페이지 | 64,115 byte | 30 | 644ms / 전송 9,962 byte |

첫 탐색 JSON이 약 99.4% 감소했다. 이는 **첫 페이지** 비교이며, 모든 페이지와 상세를 열 때의 총량이 아니다. 전송량은 브라우저 헤더를 포함한 ResourceTiming 값이다. 시간은 동일 PC의 개별 관측으로, 통제된 반복 벤치마크·p95·CWV 결과가 아니다.

- 실제 29페이지의 1,428개를 순서대로 합쳐 full 응답과 선정 ID·순서·스코어·중앙수익률 일치를 확인했다. 기간/필터는 페이지 분할 전에 적용한다.
- 2페이지는 51–100번째를 표시했다. 보로노이 `310210_M11_L0`을 클릭하면 11월·전체 기간·같은 signal_id의 상세를 가져왔다. 상세 조회 478.5ms / 60,129 byte.
- 탐색·기간 전환 전후 상세 요청은 클릭 전 0회, 플레이북 클릭 후 1회. 기간 0을 5로 바꾸지 않았다.
- 등록 화면에서 보로노이·11월 23일 피크·상세 근거가 연결됐다. 저장하지 않고 취소했다.
- 설명 2페이지 31–60번째 정상 표시. 삼성전자 검색은 1페이지로 초기화되어 전체 기간 4개 월 패턴을 표시했다.
- 해당 브라우저 흐름의 console error 0. 관련 없는 기존 안내 로그 19개는 남아 있다.

로컬 화면 근거: `output/playwright/stage4-season-detail.png`, `stage4-explanation-pagination.png`, `stage4-search-pagination.png`. 이 파일들은 Git 제외 산출물이다.

## 구현 계약

- `web/season_listing.py`: 목록/설명 필드 허용 목록과 복사 격리. 상세용 playbook·remaining_peak 표본·all_months는 요약에서 제외한다. 연도별 트랙 레코드와 기존 표 지표는 유지한다.
- `/api/seasonality/discovery`: `view=summary|explanation|full`, `offset`, `limit`(1~100), `generation_id` 추가. `count`는 필터 후 전체, `returned_count`는 현재 페이지, `next_offset=null`이면 끝이다. 기본 full은 기존 원문 행과 호환한다.
- 페이지 이동과 상세 조회에 같은 generation_id를 전달한다. 갱신된 세대와 다르면 409로 차단하고 첫 페이지 재확인을 안내한다. 오래된 후보를 새 선정으로 둔갑시키지 않는다.
- 상세는 ticker만으로 첫 패턴을 고르지 않고 **signal_id가 같은 패턴**을 선택한다. 요약을 등록 폼에 바로 전달하지 않는다.
- 늦게 끝난 이전 목록/설명 요청은 최신 화면을 덮어쓰지 않는다. 오류 시 재확인 버튼이 있고, 등록 및 상세의 연속 요청에도 최신 선택만 반영한다.
- 공개판의 기존 full 정적 파일은 클라이언트에서 표시만 페이지로 나눈다. **공개판 전송량 경량화는 아직 아니다.** 공개 스냅샷 형식 변경·공개 배포는 하지 않았다.
- 시즌 저장본을 다시 계산하지 않았으며 이전 세대 ID를 그대로 유지했다. 엔진식·Quant 점수·포트폴리오·가격·재무 변경 없음.

## 검사와 제한

- 관련 Python 회귀검사 **109 passed / 37.76초**. 전체 저장소 테스트를 의미하지 않는다.
- `node tests/js/season_listing.test.cjs`: 실제 UI 함수를 VM에서 실행해 정확한 signal 선택, 기간 0, 없는 signal 차단, 기존 full-row 호환, 이전 요청의 늦은 응답 차단을 검사했다.
- `node --check src/kr_quant/web/static/app.js`와 diff 공백 검사 통과.
- 로컬 작업 idle 확인 후 8790 서버를 재시작해 새 API를 검사했다. 운영 서버는 실행 상태로 남겼다. 작업용 브라우저는 점검 후 종료한다.
- 인수인계 스킬로 기존 변경을 보존하고 Playwright로 화면과 요청을 확인했다. web-perf 스킬의 Chrome DevTools MCP가 없어 그 정밀 진단 절차는 중단했다. 해당 도구를 연결하기 전 CWV/Lighthouse 수치를 주장하지 않는다.
- Python urllib를 통한 전체 HTTP 비교는 읽기 타임아웃으로 완료되지 않았다. 이후 PowerShell HTTP 조회로 29페이지 대조를 완료했다. 이 실패를 테스트 통과로 계산하지 않는다.

## 남은 우선 과제

1. **신뢰성:** 실제 선취매 규칙 전체를 시점별로 재현하는 OOS. 현재 재구성 기준모형의 결과를 실제 전략 검증 결과로 바꾸지 않는다. PIT 유니버스·기업행위·체결/비용 근거 필요.
2. **설명 근거:** 기존 AI 설명/플레이북의 `실패 연도 원인`에 실적 추정치 하향·수급 급감 같은 표현이 보인다. 이번 작업은 원문을 보존했으며, 개별 연도의 실제 공시/수급 근거와 대조하지 않았다. 관측 손실·업종 가설·확인된 원인을 분리하는 전수 감사가 필요하다.
3. **로딩:** 서버 내부 전체 bundle deepcopy와 필터 비용은 남아 있다. 다음에는 불변 저장본의 안전한 읽기와 요약 인덱스를 검토한다. Pre-entry/히트맵/공개 정적 파일의 추가 분할은 별도 작업이다.
4. **운영:** 실제 선정 장부의 사후 성과 연결, 전 메뉴 콜드/웜 지연 분포, 외부 API 실패·지연 상태, 실시간 시세 전용 경로 검증은 남아 있다.
