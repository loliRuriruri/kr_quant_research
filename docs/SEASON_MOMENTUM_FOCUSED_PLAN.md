## 1. 목표와 범위

이번 작업은 **시즌 모멘텀·캘린더의 종목 선정과 수익률 해석의 신뢰성**에만 집중한다.
이 문서는 실행 계획이며, 여기에 적힌 개선이 구현·검증됐다는 보고서가 아니다.

사용자가 다음을 구분할 수 있어야 한다.

- 왜 이 종목이 현재 후보인가: 거래 가능성, 시점, 계절성, 현재 확인 자료.
- 과거에 얼마나 올랐는가: 사후 최고가 통계.
- 사전에 정한 규칙으로 거래했다면 얼마였는가: 비용 차감 전략 성과.
- 그 규칙을 만들 때 보지 않은 기간에서도 유효했는가: 독립 검증 결과와 표본.
- 어떤 자료가 없어 아직 판단할 수 없는가: 명시적 결측·제외·미검증 이유.

직접 대상은 오늘의 선취매 목록, 시즌 탐색, 월별 히트맵, 이벤트 프리셋, 종목 상세 플레이북이다.
대시보드의 시즌 TOP3는 같은 데이터를 소비하므로 일치 여부만 함께 검사한다.

범위 밖: 일반 전략 랩 전면 수정, 재무 Quant 배점 변경, 매크로·수급 메뉴 개편,
모바일 디자인, 신규 테마 대량 추가, AI 모델 교체, 서버 이전, 자동매매, 사용자 포트폴리오 변경.
공통 모듈 변경은 이 메뉴의 정확성에 직접 필요한 최소 범위만 허용하고 영향 검사를 붙인다.

### 1단계 — 수익률 의미와 계산 계약 수정: 최우선

#### 대표 지표

- `historical_peak_upside`: 사후 최고 종가까지의 상승폭. 보조 통계.
- `fixed_exit_gross_return`: 미리 정한 진입·청산 규칙의 비용 전 수익률.
- `fixed_exit_net_return`: 같은 규칙에 수수료·해당 날짜/시장/상품의 세금·슬리피지를 적용한 수익률.
- `positive_net_rate`: 동일 규칙의 순수익이 양수인 관측 비율. 미래 성공 확률이라고 부르지 않는다.
- `adverse_excursion`: 보유 중 진입가 대비 최저 수익률.
- `max_drawdown`: 보유 중 자산곡선 고점 대비 하락률. 위 항목과 혼용하지 않는다.

기존 `window_end_return`을 우선 활용하되, 시작 종가 진입인지 다음 거래일 시가 진입인지 확인한다.
기존 통계에 비용만 빼고 독립 검증 성과로 이름을 바꾸면 안 된다.

#### 실행 규칙

- 기준 종가 확정 후 후보 선정 → 다음 체결 가능한 거래일 시가 진입을 기본으로 한다.
- 청산일·청산 가격 기준·최대 대기기간은 해당 평가 기간 시작 전에 고정한다.
- 시가 누락을 종가로 조용히 대체하지 않는다. 미체결·자료 부족을 구분한다.
- 시가 체결의 참여율·충격 추정은 이전에 알려진 거래량/거래대금으로 계산한다.
- 당일 전체 OHLCV로 판정하는 일봉 체결 제약은 사후 시뮬레이션 가정임을 구분한다.
- 비용 없는 추정과 비용 포함 결과는 같은 표본·체결 규칙으로 비교한다.
- 현재가 대신 최근 확정 종가를 썼으면 가격 기준과 시각을 정확히 표시한다.

#### UI 표시

대표값은 계산 근거가 확보된 고정 청산 규칙의 순수익 통계로 한다.
미확보라면 `검증 수익률 산출 전`으로 표시하고 사후 피크 통계만 보조로 제공한다.
기존 P50 환산가는 `과거 분포 환산가`이며 목표주가로 표시하지 않는다.
학습 표본 P50과 독립 검증 표본 P50은 별도 필드·라벨로 구분한다.

완료 기준:

- `100 → 95 → 90` 경로에서 사후 피크 0%, 종료 수익률 −10%가 구분된다.
- 동일 체결 경로에서 양의 비용을 적용하면 순수익이 비용 전 수익보다 높아지지 않는다.
- 미래 최고가를 실제 청산 가격으로 쓰지 않는다.
- TOP3·목록·상세가 동일 지표 정의와 값을 표시한다.

### 2단계 — 당시 선정기를 이용한 연도별 검증

단순 월별 수익률 진단과 실제 운영 선정기 재현을 별도 상태로 유지한다.
기존 홀드아웃·재현 모듈을 확장하고 새 백테스트 엔진을 중복 생성하지 않는다.

각 검증 연도 Y에 대해:

1. Y의 평가 시점 전에 공개된 가격·재무·수급·이벤트·거래상태만 선택한다.
2. 이전 연도 자료만으로 대상 월·피크일·필터·파라미터를 결정한다.
3. 해당 시점의 종목 모집단에 동일 운영 선정기를 적용한다.
4. 후보 전체·제외 이유·순위·진입/청산 규칙을 잠근 뒤 이후 성과를 계산한다.
5. 종목·설정·실패한 조합을 결과가 나쁘다고 보고서에서 없애지 않는다.
6. 다음 검증 연도로 이동하되 이후 자료가 이전 선정 결과를 바꾸지 못하게 한다.

기록: 학습/검증 기간, 입력 해시, 모델·설정 버전, 후보 순위, 제외 원인,
체결 여부, 비용 전후 성과, 보유 기간, 실제 표본 수, 벤치마크, 원천 부족.

벤치마크는 같은 보유 기간의 해당 시장 지수 및 종목 단순 보유와 비교한다.
배당 포함/미포함 기준을 맞추고, 지수 원천이 없으면 초과수익은 미산출로 둔다.

과거 종목 모집단이 미확보이면 `현재 종목군 조건부 분석`까지만 허용한다.
현재 재무·테마·수급을 과거 자료로 대신 채우지 않는다.
전망 성과 추적은 기존 선정 기록을 활용하며 과거 기록을 현재 시점에 소급 생성하지 않는다.

완료 기준:

- 미래 가격·미래 정정공시·미래 이벤트를 추가해도 과거 후보와 당시 파라미터가 불변이다.
- 과거 입력 누락은 `INSUFFICIENT_DATA`로 남고, 좋은 결과만 집계되지 않는다.
- 진단 결과와 전체 운영 선정기 검증 결과의 상태가 API·화면에서 구분된다.

### 3단계 — 표본·이벤트·날짜·정렬 신뢰성

#### 표본과 탐색 편향

- 학습 연수, 검증 연수, 완료된 거래 수, 미체결 수를 따로 표시한다.
- 기존 신뢰구간·다중 조합 보정 기능을 재사용한다.
- 한 해씩 제외했을 때 중앙값·승률·순위가 얼마나 바뀌는지 진단한다.
- 낮은 표본·특정 한 해 의존·시장 공통 상승 효과를 독립적으로 설명한다.
- 탐색한 종목×월×파라미터 수와 모델 수정 이력을 기록한다.
- 표본 수만으로 `고신뢰`를 주지 않는다. 독립성과 자료 적합성도 요구한다.
- 점수/순위 변경 전 기존 후보와 변경 후보의 이동 및 제외 사유를 비교한다.

#### 이벤트 근거

- 일반 계절 가설, 확인된 기업 사업 노출, 날짜가 있는 공식 이벤트를 구분한다.
- 근거에는 원천, 발표/관측 시각, 유효기간, 해당 기업과 연결되는 사실을 저장한다.
- AI 설명 문장이나 설명의 유창함을 신뢰도 근거로 쓰지 않는다.
- 근거 미확보 시 `이벤트 원인 미확인`으로 표시한다.
- 기존 이벤트 최대 10점의 효과를 가점 포함/제외 비교로 검증한다.
  독립 근거가 없는 설명 가점을 유지할지 수정할지는 비교 결과와 정책 버전에 남긴다.
- 확정된 출처 없는 새 촉매를 만들기 위해 LLM 호출·뉴스 수집을 반복하지 않는다.

#### 날짜와 순위

- 무조건 28일 제한 대신 실제 월말과 시장 거래일을 처리한다.
- 피크 날짜는 중앙값뿐 아니라 연도별 범위·편차도 표시한다.
- 피크 30~15일 전 규칙이 달력일인지 거래일인지 명시한다.
- 연말→다음 해, 휴장일, 월말, 신규상장과 불완전 월 표본을 검증한다.
- 과거 자료가 8거래일 있다고 완전한 월로 간주하지 않는다. 기대 거래일 대비 실제 범위를 확인한다.
- `현재 진입 단계 우선` 정렬과 `수익률 우선` 정렬의 의미를 구분한다.
- 종목이 여러 월/이벤트에 중복되면 기본 TOP목록의 대표 패턴 선택 규칙을 고정하고 설명한다.

완료 기준: 작은 표본·근거 없는 이벤트·흔들리는 날짜가 확정적 신호로 표현되지 않는다.
기본 정렬 변경은 재현 가능한 비교 근거와 모델 버전을 남긴다.

- 가격 날짜가 같아도 정정 내용·거래상태·기업행위·이벤트·비용·설정이 바뀌면 관련 캐시를 무효화한다.
- 최초 로딩, 캐시 조회, 필터 변경, 상세 열기·닫기의 PC 동작을 검사한다.
- 입력 오류 때 이전 정상 자료는 보존하되 현재 결과처럼 표시하지 않는다.
- 성능은 수정 전후 같은 자료·조건으로 비교한다. 결과를 빠르게 만들기 위해 검증 구간을 몰래 줄이지 않는다.

완료 기준: 시즌 관련 회귀와 PC 흐름 검사가 통과하고, 남은 원천 부족과 적용 범위가 기록된다.
기능 동작 통과를 투자 성과 검증 통과로 승격하지 않는다.

## 5. 필수 검증 목록 — 필요한 것만 실행

아래 동작을 기존 테스트에 추가하거나 누락된 경우에만 새 테스트를 만든다.

| 검증 | 기대 결과 |
|---|---|
| 하락 경로 | 사후 피크 0%와 실제 손실 구분 |
| 고정 청산·비용 | 미래 최고가 미사용, 같은 체결의 순수익≤비용 전 수익 |
| 미래 자료 추가 | 과거 후보·파라미터 불변 |
| 당시 입력 부족 | 미검증/자료 부족, 현재 자료 대체 없음 |
| 손실 연도·미체결 | 표본과 제외 장부에서 사라지지 않음 |
| 단절·기업행위 | 미확인 보정으로 수익 만들지 않음 |
| 표본·이벤트 | 근거 부족이 고신뢰·확정 촉매로 표시되지 않음 |
| 월말·연말·휴장 | 명시된 거래일 정책과 일치 |
| 같은 날짜 정정·설정 변경 | 관련 계산 캐시 재사용 차단 |
| 메뉴 연동 | 동일 조건 TOP3·목록·상세의 종목/순위/수치 일치 |
| 장애·성능 | 정상 자료 보존, PC 탐색 퇴행 없음 |

관련 테스트 후보: `test_remaining_peak*`, `test_pre_entry_ranking`, `test_pre_entry_replay`,
`test_season_holdout`, `test_season_snapshot`, `test_season_listing`, `test_seasonality*`,
`test_historical_features`, `test_statistical_reliability`.
매 단계에서 변경한 기능에 해당하는 것만 선택한다. 최종에 관련 검사 묶음을 한 번 실행한다.
공통 모듈을 수정했으면 그 소비 경로의 검사만 추가하고, 근거 없이 저장소 전체 테스트를 반복하지 않는다.
운영 `.env`·DB·원천을 쓰지 않는 격리 환경과 fixture를 기본으로 한다.
실제 원천 검사는 필요할 때만 별도로 수행하고 수집·재계산·공개배포를 진단 명령에 숨기지 않는다.

## 6. 결과 상태와 완료 판정

상태는 점수 평균으로 결정하지 않는다. 필수 조건 하나가 막혀 있으면 그 범위의 검증을 승격하지 않는다.

- `DESCRIPTIVE_ONLY`: 사후 가격 통계만 제공 가능.
- `EXPERIMENTAL`: 규칙 평가 가능, 역사 입력·편향·체결 가정 등에 제약 있음.
- `INSUFFICIENT_DATA`: 필요한 원천 또는 유효 표본 부족.
- `VALIDATED_FOR_SCOPE`: 명시한 기간·모집단·규칙에서 사전 정의한 검증 조건 충족.

`VALIDATED_FOR_SCOPE`도 미래 수익 보장이 아니다. 표본·기간·비용·벤치마크·잔여 한계를 같이 제공한다.
검증한 전략이 비용 후 부진하면 부진한 결과를 그대로 보고한다. 수익이 나올 때까지 설정을 바꾸지 않는다.
새로운 설정 탐색을 했다면 별도 모델 버전과 새 검증 계획으로 기록한다.

기업행위/상폐정산/당시 모집단 등 자료가 없으면:

1. 코드 처리와 누락 차단 검증은 완료할 수 있다.
2. 전체 역사적 성과 검증은 `BLOCKED_BY_DATA`로 남긴다.
3. 부족한 원천·기간·종목 범위와 확보 방법을 적고 같은 빈 결과를 반복 조사하지 않는다.

## 7. 토큰·시간 절약 규칙

- 이번 문서와 최신 인계 절, 직접 수정 함수·테스트만 읽는다. 이전 대화·전체 문서를 반복 독해하지 않는다.
- 전체 저장소 재감사, 다른 메뉴 개선, UI 전면 재작성, 부가 AI 기능 제안은 하지 않는다.
- 기존 함수·스냅샷·검증기를 재사용한다. 상태 이름만 다른 별도 엔진을 추가하지 않는다.
- 테스트 실패는 재현→최소 수정→해당 검사 순으로 처리한다. 실패를 숨기기 위해 단언을 약화하지 않는다.
- 장기 데이터 재수집·전체 parameter 탐색·LLM 반복 호출은 기본 작업에 포함하지 않는다.
- 일상 진행은 이 지시서 순서로 이어가며, 단계별 불필요한 승인 질문을 반복하지 않는다.
- 새 비용·계정·외부 공개 범위가 필요한 경우에만 필요한 선택을 구체적으로 요청한다.
- 진행 보고는 `수정 내용 / 검증 결과 / 다음 항목`을 짧게 전달한다.
- 실제 변경·실패·미해결 우려가 없으면 같은 테스트와 측정을 반복하지 않는다.

## 8. 산출물과 인계

문서를 여러 개로 늘리지 않는다.

1. 이 지시서: 작업 범위·정책·완료 기준.
2. 실행 후 `docs/SEASON_MOMENTUM_FOCUSED_RESULT.md`: 변경, 검증, 순위 영향, 미해결 원천을 통합 기록.
3. 필요할 때만 `output/audit/season-focused/`에 작은 재현용 JSON/XML과 대표 PC 화면을 저장.

결과 보고서에는 다음을 포함한다.

- 기준/최종 커밋, 수정된 파일, 계산/스냅샷 버전.
- 기존 피크 통계와 새 순수익 지표의 차이, 같은 표본 비교.
- 기존/변경 후보 순위와 이동·제외 이유.
- 학습/검증 기간, 실제 표본, 비용, 벤치마크와 자료 누락.
- 실행한 검사 명령·통과/실패 결과·증거 경로.
- 코드 보완 완료 범위와 역사적 성과 검증 미완료 범위.

단계별로 관련 파일만 커밋하고 복구 방법을 메시지에 적는다.
코드 커밋, 원천 갱신, 공개 스냅샷 배포의 완료 여부는 따로 기록한다.
시즌 메뉴가 정상 표시된다는 이유로 전체 모델 신뢰성이 검증됐다고 선언하지 않는다.
