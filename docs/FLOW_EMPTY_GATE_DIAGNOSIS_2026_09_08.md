## 3. 원인 사슬

```
18:00 KST
  → expected_price_date() = 2026-09-08
  → 실제 창고
       prices.parquet     max 2026-09-07
       krx_status.csv     max 2026-09-07  (09-08 행 없음)
       toss cache to      2026-09-07      (09:55 스캔)
  → 게이트가 09-08만 ‘현재’로 인정
  → 표 0 / AI 근거 0
```

세 시계가 어긋난 것이 아니라, **한 시계(18:00 규칙)만 앞서고 세 원천은 일치**했다. 게이트가 앞선 시계를 정답으로 썼다.

### 3-1. 스마트 수급 (토스)

`gate_toss_payload` → `toss_reason`:

1. 종목이 `active_tickers(expected=09-08)`에 있어야 함  
2. `row.to == 09-08` 이어야 함 → 아니면 `FLOW_DATE_MISMATCH`  
3. 일별 `max(date) == 09-08` 이어야 함 → 아니면 `FLOW_WINDOW_UNVERIFIED`

실측 (수정 전, 20:49 KST):

| 이유 | 건수 |
| --- | ---: |
| `FLOW_DATE_MISMATCH` | 142 |
| `STATUS_UNVERIFIED_OR_INELIGIBLE` | 18 |
| 통과 | **0** |

같은 캐시를 기대일 09-07로만 다시 검사하면 **141/160 통과**. 18종목은 거래상태 미적격, 1종목은 윈도 미달. 원본 dual 35 → 게이트 후 28.

즉 160종목 스캔은 유효했고, 필터 날짜만 하루 미래였다.

적용 경로: `/api/flow` GET, 수급 다시 스캔 결과, 빈집·기술타점·성과검증, 테마 스크리너 수급 집합, 시즌 수급 확인, 근거 레지스트리.

### 3-2. 메이저 수급 (KIS)

`active_tickers`가 `krx_status.csv`에서 **as_of_date == expected(09-08)** 인 행만 유니버스로 썼다. 09-08 행이 없으면 유니버스 = 공집합.

그다음 `gate_official_rows`가 외국인·기관 **양쪽 모두 09-08 확정 행**과 그 유니버스 교집합만 남긴다. 유니버스가 비면 저장 1만 행이 있어도 현재 신호 0.

`events_payload`의 cum5 / consecutive / paired / turns 가 빈다. `active`가 toss로 넘어가도 토스 쪽은 3-1에서 이미 0.

### 3-3. 노란 AI 카드

`/api/flow/tier1-briefing`은 표 API와 별도 스캔을 하지 않고 `events_payload()` 결과를 그대로 근거로 쓴다.

이벤트 표가 비면 `briefing_candidates()`가 `missing: ["investor_flow_events"]`를 붙인다. 재균형 표본·저장 건수 fallback이 같이 막히면 `evidence=[]` → `TIER1_EVIDENCE_MISSING`.

문구 “수급 브리핑에 사용할 실제 종목 데이터가 없습니다”는 **저장 없음이 아니라 게이트 이후 현재 후보 없음**을 그렇게 표현한 것이다.

스마트 수급 화면도 같은 `/api/flow/tier1-briefing`을 부른다. 토스 표가 비는 것과 노란 카드는 한 게이트의 두 표면이다.

## 5. 수정 내용 (이미 적용)

저장 숫자를 만들지 않는다. 오늘 세션이 없으면 어제 세션을 **어제라고 표시**한다.

1. **거래상태 유니버스**  
   기대일 행이 없으면 `krx_status`의 기대일 이하 최신일을 유니버스로 쓴다. 상태 파일 자체 없음은 계속 공집합.

2. **토스 표시 세션** (`toss_session`)  
   - 캐시에 기대일이 있으면 기대일  
   - 없고, 캐시 최신 `to`가 창고 최신 상태일과 같으면 그 세션을 표시 + `session_fallback`  
   - 캐시가 창고보다 오래되면 예전처럼 차단 (예: 창고 09-07인데 캐시 09-04)

3. **브리핑**  
   이벤트 표가 비어도 재균형 표본 → 저장 건수 순으로 근거를 남긴다. 노란 카드는 ‘저장 자체가 없을 때’만.

4. **need_scan**  
   미적격 몇 종목이 빠졌다고 목록 전체를 스캔 필요로 만들지 않음. 통과 행이 0일 때만.
