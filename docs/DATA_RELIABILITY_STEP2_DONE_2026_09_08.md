## 완료 기준 및 수정

이 단계의 범위는 **과거·미확정·거래불가 자료가 현재 후보나 현재 확인 신호로 사용되지 않게 하는 것**이다. 원천 공급자의 최신 자료 제공이나 투자성과 자체를 보장하는 단계가 아니다.

1. `flow/reliability.py`에 공통 검사 도입. 현재일 ACTIVE·양수 종가/거래량·위험분류 확인. 토스 수급 종료일, 일별 날짜·값, 요청 기간 충족, 중복일자, 미확정 표시, 중복 종목 검사. 누락/미확인/충돌은 제외한다.
2. 스마트 수급의 모든 후보 분류, 빈집·복귀, 기술 타점, 직접 종목 진단에 적용. 분류별 별도 JSON 객체도 같은 종목의 기준 행을 사용하도록 통일했다. 제외된 종목을 포함한 과거 집계 통계는 재사용하지 않는다.
3. 테마 스크리너의 수급 집합, 시즌 모멘텀 캘린더의 수급 확인값, AI 설명 근거와 근거 레지스트리가 동일 검사를 통과한 값만 사용한다. 날짜 증거가 없는 예전 코드 목록 fallback은 차단한다. Quant 점수에 수급을 새로 합산하지 않는다.
4. KIS는 외국인·기관 양쪽 모두 기준일 확정 행이 있어야 현재 신호에 사용한다. 투자자 구분별 오래된 마지막 관측값도 제외한다. 종목 상세의 확정 이력은 유지하되 현재 조건 불충족이면 현재 누적 신호는 빈 값이다. 누적 계산 순서가 오래된 값 우선이던 경로도 최신 우선으로 교정했다.
5. 기술지표 가격일과 현재 후보 기준일이 다르면 기술적 유효 신호를 표시하지 않는다. 가격 자료가 없을 때 각 분류의 오래된 기술값도 무효화한다.
6. PC 화면에 검증 건수/제외 이유 표시. 브라우저 수급 메모리는30초 이후 재확인하고, 서버 캐시는 거래상태·수급 파일·기대일 변경을 반영한다. 메뉴 GET은 원천 수집을 실행하지 않으며 안내도 실제 동작과 일치시켰다.
7. 시즌 스냅샷 지문에 거래상태와 공통 검사 코드 변경을 포함하고 기본5년 스냅샷을 재생성했다. 관심종목은 사용자 목록이므로 삭제하지 않으며, 현재 수급 진단만 차단 조건을 적용한다. 순수 Quant 순위는 기존 엔진/적격 기준을 유지한다.
