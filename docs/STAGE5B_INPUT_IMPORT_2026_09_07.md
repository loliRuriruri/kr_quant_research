# 과거 입력 파일 로더·누락 장부 — 기반 작업 정리

작업 전 저장점 `7200f80`. 재개 스킬로 이전 결과를 확인하고 실제 파일을 읽는 입력 경로와 사례별 실패 장부를 연결했다. **전체 과거 성과 검증 완료가 아니다.**

## 구현 범위

- `research/feature_import.py`: JSON(records/rows/list) 또는 Parquet의 명시적 버전 입력을 읽어 기존 `select_as_of_features`로 연결한다. ticker/kind/available_at/effective_at/valid_until/source/data/sha256 계약을 요구한다.
- 레거시 as_of_date/생성일을 공개시각으로 바꾸거나 현재 값을 과거 특징으로 대입하지 않는다. 누락 열·손상·잘못된 종류/종목·읽는 중 파일 변경을 구분한다.
- 종목 × 판단시각의 전체 요청 분모를 유지한다. 차단 사례에도 항목별 누락 이유를 남기며 정상도 SELECTED_UNVERIFIED다. 전체 역사적 유니버스 커버리지로 표시하지 않는다.
- `scripts/import_historical_features.py`: 원천 읽기만 수행하고 새 이름의 불변 결과 파일을 작성한다. 기존 출력 경로는 거절한다. 수집 API·운영 재계산·서버 재시작·공개 배포 없음.
- 기본은 알려진 로컬 점수 이력·수급 파일과 지정 이벤트 이력 경로를 확인한다. 이는 전체 디스크 검색이 아니며, 계약을 만족하는 별도 자료가 있으면 `--archive`로 명시해야 한다.

- `data/cache/investor_flow.json`: rows 160개. 같은 입력 계약 열 누락으로 INCOMPATIBLE_SCHEMA.
- `data/research_inputs/event_history.json`: 지정 경로에 파일 없음. 현재 코드의 이벤트 지식베이스를 과거 이력으로 변환하지 않음.
- 읽은 두 원천은 읽기 전후 해시 동일. 결과는 `output/audit/feature-import-20260907.json`에 로컬 저장(Git 제외).

**이 결과는 자료가 전혀 없거나 종목이 투자 부적격이라는 뜻이 아니다.** 해당 기존 형식만으로 과거 재현에 필요한 입력을 입증·변환할 수 없다는 뜻이다. 이번 로더는 원시 재무 계산기/외부 수집기가 아니며 정상 파일의 출처 진실성도 독립적으로 인증하지 않는다.

## 남은 작업과 다음 순서

과거 검증 기반은 시점 검사 → 월 패턴 → 입력 버전 → 점수/순위 → 파일 로더/누락 장부까지 갖췄다. 더 많은 빈 어댑터를 만드는 것보다 부족한 원천과 실제 UI 개선을 구분해 진행한다.

1. **다음 우선 작업: 성능·실시간.** 남은 무거운 메뉴의 실측 로딩, 서버 bundle 복사·공개 파일 전송량, 가격 전용 갱신과 작업/기준일 상태 UX를 확인하고 개선한다. 전 메뉴 실시간 완료는 아직 아니다.
2. **그다음: 통합 검사.** 메뉴 간 종목·기준일·선정ID 일치, 빈 자료·API 장애·재시작 복구, 승인된 배포 경로 점검.
3. **별도 데이터 의존 과제: 선정 성과 신뢰성.** 당시 거래상태/상폐/재무 정정/수급/이벤트 원천 확보 및 변환, 가격 조정·기업행위·체결 비용, 전체 과거 선정/제외 장부와 OOS. 현재부터 축적하는 실측 장부는 별도로 유지한다.

따라서 남은 범위는 **개선·검증 2묶음 + 데이터 의존 신뢰성 1묶음**이다. 과거 원천이 확보되지 않은 상태에서 ‘몇 번 더 하면 100%’나 상용급 완성도를 약속하지 않는다. 이번 단계 이후 과거 검증 코드 기반 확장을 잠시 마무리하고 성능 작업으로 전환한다.
