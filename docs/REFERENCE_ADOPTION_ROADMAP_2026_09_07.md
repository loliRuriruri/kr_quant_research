# 외부 리서치 서비스 참고 도입 로드맵

작성일: 2026-09-07 · 대상: KR Quant Research

## 결론

Seeking Alpha와 Camel Research에서 우선 참고할 것은 기사·점수의 복제가 아니라 **선정 근거를 열어 보는 구조, 반대 근거, 선정 당시 기록과 이후 성과의 연결**이다. 새 메뉴를 늘리기보다 기존 Quant·시즌 모멘텀·종목 상세에 이 구조를 통합한다.

우선순위는 **기존 계산 검증 → 선정 기록 고정 → 성과·계절성 검증 → 설명 패널 → 추가 정보 → 통합 배포 검증**이다. 아래는 과거 작업의 1~8단계와 구분되는, 이번 외부 참고 도입을 위한 새 1~6단계다.

이번 작업은 코드·공개 페이지 검토와 계획 문서 작성이다. 엔진 추가 수정, 전체 재계산, 커밋, 서버 재시작, 공개 배포는 실행하지 않았다.

## 1. 확인 범위와 현재 상태

- 작업 기준 HEAD: `bd09ece`. 앞선 신뢰성 패치가 미커밋 작업트리에 있으므로 이를 보존해야 한다.
- 앞선 검사: 선택된 테스트 104개 통과. 전체 제품의 무결성이나 투자 성과를 입증하는 숫자는 아니다.
- 브라우저 fixture의 14메뉴 전환 반응은 63~150ms였다. 실제 외부 API 완료 시간·운영 p95·개선 전 대비 속도 향상은 미검증이다.
- 저장된 2,765종목을 이용한 제한적 peer 재생에서 532종목의 가중 점수 차이를 확인했다. 최대 절대 차이 약 10.7412점. 게이트·누락 지표까지 다시 계산한 전체 랭킹 비교는 아니다.
- 공개 사이트의 설명·노출 UI를 확인했다. Camel의 로그인 전용 데이터, 내부 계산식, 실시간 정확도, API 제공 권한은 확인하지 않았다.
- 관련 기존 기록: [신뢰성 감사](AUDIT_RELIABILITY_2026_09_07.md), [인수인계](../HANDOFF.md).

## 2. 참고할 요소와 재사용할 기존 기능

Seeking Alpha는 섹터 상대 팩터 평가와 원지표·섹터 평균을 펼쳐 보는 방식을 설명한다. EPS 추정치 수정도 별도 팩터로 사용하지만, 한국 거래소 상장종목의 평가값을 직접 공급하는 자료로 간주해서는 안 된다. [공식 FAQ](https://help.seekingalpha.com/premium/quant-ratings-and-factor-grades-faq)

Camel 공개 화면에는 강세·약세 근거, 신호 후속 성과, 회계 지표 경고, 업종 상대강도, 저장된 리포트 요약을 연결하는 구성이 있다. 이를 우리 데이터로 구현하는 참고 사례로 삼는다. 화면에 기능이 있다는 사실과 그 계산이 검증됐다는 사실은 다르다. [공개 대시보드](https://dashboard.camelresearch.com/)

### 새로 확인한 선행 정비 사항

1. `events/backtest.py`의 `market_mean_series = table.mean(axis=1)`은 **주가 수준의 평균**이다. 이를 두 시점에서 나눈 수익률은 동일가중 시장 수익률이나 공식 지수 수익률이 아니다. 고가주·구성종목 변경·가격 단위 변화에 영향을 받으므로 초과수익률 해석부터 바로잡아야 한다.
2. 같은 함수는 공시 날짜의 종가를 출발값으로 사용한다. 이는 공시일 종가 이후 가격 반응 통계로는 정의할 수 있지만, 장후 공시까지 포함한 실제 체결 가능 전략 성과와 같지 않다. 두 통계를 구분해야 한다.
3. `sector/ranking.py`의 비교값은 적격 종목의 3개월 수익률 평균이다. 이 값을 KOSPI 수익률로 설명해서는 안 된다. 비교집단·가중 방식·생존편향 한계를 표시해야 한다.
4. `factors/scorecard.py`는 점수 구간으로 `STRONG_BUY` 등 문구를 만든다. 해당 변환만으로 거래 적격성·재무 커버리지·OOS 성과가 입증되지는 않는다. ‘상위 점수/추가 확인 필요’ 등 근거 중심 표현과 적격 상태를 분리하는 편이 적절하다.

이 항목들은 코드 검토로 확인한 설계·계산 문제다. 이번 문서 작성 중 수정하거나 각 영향 규모를 재산출하지 않았다.

## 3. 단계별 실행 계획

### 1단계 — 기준선 고정과 성과 계산 정비

**목표:** 잘못된 기준 위에 새로운 정보를 쌓지 않는다.

- 기존 미커밋 변경을 검토하고 사용자 변경과 분리한다. 구현 착수 시 상세 변경 메시지를 갖춘 Git 저장점과 데이터 세대·설정·소스 해시 목록을 남긴다. Git만으로 사용자 데이터가 복원되지는 않는다.
- 원본 데이터를 수정하지 않는 복제본에서 구/신 전체 Quant 계산을 재생한다. 동일 입력·설정으로 비교하고 적격 수, 제외 이유, 팩터 기여, TOP 20/30/100 교체 원인을 기록한다.
- 이벤트 벤치마크를 공식 KOSPI/KOSDAQ 또는 명시적 포트폴리오 수익률로 교체한다. 원천 미확보 시 초과수익률은 미산출한다.
- 공시 반응 통계와 체결 시뮬레이션의 시작 시점·진입 가격을 분리한다.
- 점수 등급을 자동 매수 권고처럼 표현하는 곳을 정리한다.

**통과 기준:** 재실행 결과 재현, 모든 후보 변동 원인 추적, 수작업 소형 표본과 수익률 일치. 고가주·액면분할·장후 공시·가격 누락·거래정지 회귀검사 포함. 점수 변화가 크다는 이유만으로 실패도 성공도 판정하지 않는다.

**산출물:** 구/신 비교 보고서, 계산 정의서, 회귀검사, 롤백 가능한 코드·데이터 기준선.

### 2단계 — 선정 시점 기록과 메뉴 공통 근거 연결

**목표:** ‘그날 왜 뽑혔는지’를 나중에 바꾸지 못하게 기록한다.

- 공통 `signal_id`를 부여한다. 종목코드, 생성 시각, 데이터 기준일, 전략·모델 버전, 대상 이벤트, 예정 진입/종료 규칙, 선정 점수·근거, 상태 게이트와 소스 해시를 저장한다.
- 점수 랭킹, 오늘의 Top 3, 시즌 캘린더가 같은 후보 집합·정렬 기준·스냅샷에서 파생되도록 한다. 필터 차이는 화면에서 설명한다.
- `web/evidence.py`의 메뉴 단위 근거를 종목·신호 단위까지 확장한다. 사용자 편집 포트폴리오와 자동 선정 장부는 별도 저장한다.
- 동일 작업 재시도는 중복 신호를 만들지 않는다. 정정은 원본을 덮어쓰지 않고 정정 버전과 이유를 추가한다.
- 과거 선정 장부가 없는 기간은 ‘재구성 백테스트’로 표시한다. 실제 당시 추천 이력처럼 소급 생성하지 않는다.

**통과 기준:** 동일 필터에서 Top 3 = 공통 상위 목록의 첫 3개. 상세화면도 같은 신호 ID·기준일·수치 사용. 재시도 중복 0건, 정정 이력 보존, 결측값을 0이나 가상 시세로 채우지 않음.

**산출물:** 선정 장부와 공통 응답 계약, 메뉴 간 일치 검사.

### 3단계 — 선정 신뢰성 검증: 사후 성과와 시즌 OOS

**목표:** 그럴듯한 계절 패턴과 재현 가능한 선정 능력을 구분한다.

- 고정 신호별 다음 체결 가능 시점부터 D+1/5/20거래일 성과, 벤치마크 대비 성과, 보유 중 최대 불리한 가격 변화, 관측 수·진입 불가 수를 계산한다.
- 시점·시장별 거래비용 설정을 사용한다. 세율은 적용 연도와 시장의 확인된 규칙을 사용하며 예전의 단일 세율을 전 기간에 고정하지 않는다.
- 거래정지·상하한가·거래량 부족은 일봉만으로 체결을 확정하지 않는다. 보수적 체결 규칙 또는 체결 불확실 상태를 남긴다.
- 아직 20거래일이 지나지 않은 결과는 ‘관측 중’이다. 누락·미체결·상장폐지를 임의 제거해 승률을 높이지 않는다.
- 시즌은 각 연도의 과거 데이터만으로 대상 월·종목·진입/종료 규칙을 정하고 다음 연도를 평가한다. 전체 기간에서 찾은 피크 날짜를 과거 검증에 역으로 사용하지 않는다.
- 학습/시험 경계를 넘는 보유 구간과 중복 이벤트를 분리하고, 여러 종목·월·규칙을 탐색한 효과를 고려한다. 표본 수·신뢰구간·연도별 편차·비용 민감도를 공개한다.
- ‘기간 중 사후 최고가까지 상승률’, ‘사전 고정 종료일 수익률’, ‘실제 관측 성과’를 별도 표시한다. 최고가 도달 통계를 기대 실현 수익률·미래 확률로 쓰지 않는다.
- 과거 유니버스·상장폐지 자료가 없으면 생존편향 미해결 상태로 제한한다.

**통과 기준:** 미래 데이터를 바꿔도 과거 신호가 변하지 않는 검사, 미완료 월 배제, 지연 공시 PIT 검사, 비용 후 OOS 결과와 표본 공개. 성과가 나쁘면 나쁘게 표시한다. 통계적 근거가 부족한 모델은 실험 상태로 유지한다.

**산출물:** 실제 신호 성적표 + 별도로 구분된 재구성/OOS 보고서. 20거래일 실관측을 개발 속도로 단축할 수는 없다.

### 4단계 — 종목 상세 설명과 반대 근거 강화

**목표:** 메뉴 설명 대신 ‘이 종목이 선정된 이유’를 설명한다.

- 기존 팩터 카드에 원지표, 단위, 공시·가용 시점, 업종 중앙값, 비교 표본 수, 적용된 fallback 집단, 점수 기여를 추가한다. 자체 등급을 Seeking Alpha 등급처럼 표기하지 않는다.
- 상세 패널을 선정 이유 / 반대 근거 / 확인할 촉매 / 무효화 조건 / 데이터 한계로 구성한다.
- 계절성 근거와 올해 실제 공시·수급 확인을 분리한다. ‘9월이라 실적 모멘텀’ 같은 추정 문장은 확인된 사실처럼 노출하지 않는다.
- LLM은 제공된 근거를 설명하며 점수·수익률·일정을 생성하지 않는다. 출처 ID 없는 주장, 다른 회사 자료 혼입, 숫자 불일치를 검사한다.
- AI 실패 시 원수치와 규칙 기반 설명을 유지하고 화면 조회마다 재생성하지 않는다.

**통과 기준:** 모든 수치의 원천 추적, 근거 없는 고유명사·촉매 차단, 낙관/비관·표본 부족·API 실패 사례의 일관된 화면 표시. 상세 선택 종목과 근거 종목이 동일함을 검사한다.

**산출물:** 기존 종목 드로어의 근거 탭, 전 메뉴 공통 링크, 설명 회귀검사.

### 5단계 — 회계·업종·이벤트 정보의 선택적 보강

**목표:** 검증 가능한 추가 정보만 기존 화면에 붙인다.

- 회계: 순이익과 CFO 괴리, 매출 대비 채권·재고 변화 등을 계산하되 연결/별도·누적/분기·단위를 통일한다. 금융업 등 비적합 지표는 N/A 처리한다. 경고를 회계 부정 확정 판정으로 표현하지 않는다.
- 업종: 1M/3M 상대강도와 날짜별 궤적을 저장한다. 분류체계와 분류 기준일을 고정하고 공식 지수와 자체 업종 포트폴리오를 구분한다.
- 이벤트: 공시·기업 IR·공식 행사 일정에 원문 링크, 발표 시각, 확정/추정 상태, 변경 이력을 붙인다. 테마 연관성만으로 올해 수혜가 입증됐다고 설명하지 않는다.
- EPS 전망 수정: 합법적으로 사용 가능한 시점별 컨센서스·수정 이력·커버리지가 확보된 경우에만 별도 도입한다. 미확보라면 이 부분을 보류하고 나머지를 진행한다.
- 처음에는 보조 정보로만 제공한다. 기존 품질·성장·모멘텀과 중복되는 항목을 이중 가산하지 않는다.

**통과 기준:** 원천·가용 시점·계산 단위 검증, 분류 혼용 방지, 결측/지연 상태 노출. 점수 편입은 별도 OOS 증분 효과·회전율·비용·안정성 검증 후 결정한다.

**산출물:** 회계 경고·업종 궤적·이벤트 근거 패널. 컨센서스는 데이터 확보에 따른 선택 산출물.

### 6단계 — 실데이터 통합·속도·운영 검증과 릴리스

**목표:** 계산이 맞고, 메뉴끼리 맞고, 정상 운영되는 상태로 배포한다.

- 실데이터 복제본에서 대시보드 → 랭킹 → 종목 상세 → 시즌 → 추적 장부를 검증한다. 수급/이벤트처럼 다른 기준일을 쓰는 데이터는 차이를 명시한다.
- 콜드/웜 캐시, 대량 목록, 모바일, 느린 네트워크, API 오류, 수집 중 조회, 이전 세대 응답 지연을 검사한다.
- 화면 반응, 데이터 준비, 외부 호출을 별도 측정한다. 동일 데이터·장비에서 반복 측정하여 p50/p95, API 호출 수, 오류율을 보고한다.
- 외부 수집·AI 생성은 배경 작업에서 수행하고 페이지 이동은 저장된 결과를 읽는다. 클릭마다 크롤링하지 않는다.
- 스마트 실행에서 수집 → 품질 검사 → 계산 → 신호 저장 → 캐시 세대 전환을 단계별 관측 가능하게 만든다. 실패를 성공으로 표시하지 않고 마지막 정상 세대를 유지한다.
- 저장 형식 변경은 백업과 마이그레이션·복구 검사를 포함한다. 코드 롤백과 데이터 롤백을 따로 준비한다.

**통과 기준:** 동일 입력의 메뉴 간 수치/순위 불일치 0건, 사용자 데이터 변경 없는 테스트, 실패/복구 검사 통과. 성능 예산은 실제 기준선 확보 후 고정하며, 기존 fixture 수치를 실데이터 SLA로 사용하지 않는다.

**산출물:** 통합 QA, 성능 보고서, 상세 릴리스 노트, 복구 절차. 승인된 시점에 재시작·공개 배포.

## 4. 수집·이용 원칙

- 공개 방법론·UI 구조는 참고하되, 유료 평가값·기사 전문·로그인 제한 데이터의 무단 복제나 접근 제한 우회는 하지 않는다.
- 수집 전에 이용 조건, API/내보내기 제공 여부, 재배포 권한, 호출 제한을 확인한다. 공개 조회가 가능하다고 대량 재게시 권한까지 있다고 가정하지 않는다.
- 실제 계산은 사용 권한이 확인된 KRX·OpenDART·기업 IR 등 원천 자료 중심으로 한다. 시장 데이터 재배포도 제공자의 이용 조건을 확인한다.
- 수집 레코드에는 source URL, source ID, 발표/가용/수집 시각, 종목·이벤트 매핑, 원본 해시를 기록한다. 회사명만의 모호한 매핑은 보류한다.
- 변경 감지·증분 수집·재시도 간격·캐시를 사용한다. 외부 정보 부족을 AI 추측으로 메우지 않는다.

## 5. 릴리스와 착수 순서

1. **첫 착수:** 1단계의 전체 Quant 구/신 재생과 이벤트 성과 기준 정비. 지금은 외부 크롤러보다 이것이 중요하다.
2. **첫 사용자 체감 릴리스:** 2단계 장부와 3단계의 관측 중 성적표, 4단계 근거 화면. 실관측 기간이 부족해도 미완료 상태를 정직하게 표시하며 제공할 수 있다. 이 릴리스도 6단계의 해당 범위 QA를 통과해야 한다.
3. **시즌 신뢰성 판단:** 3단계 OOS 결과로 선정 기준을 유지/보류/수정한다. 좋은 결과를 만들기 위해 시험 구간을 반복 튜닝하지 않는다.
4. **추가 정보 릴리스:** 5단계의 검증된 항목만 순차 적용한다. EPS 자료 부재로 전체 개선을 멈추지 않는다.
5. **최종 통합:** 6단계 전체 QA와 상세 세이브포인트 후 운영 반영한다.

완성도는 임의의 90%·100% 수치 대신 재현성, 출처 커버리지, 메뉴 일치, OOS·실관측 표본, 오류 복구, 운영 지연으로 평가한다. 외부 사이트와 비슷한 화면을 만드는 것 자체는 종목 선정 신뢰성의 증거가 아니다.
