# 5A단계 — 가격 관측과 원인 가설 분리

## 판단: 설명 정비 완료, 실제 선취매 전체 OOS는 미완료

시즌 설명이 실제 해당 연도의 공시/수급 증거 없이 업종 위험 문구를 하락 원인으로 단정하던 오류를 수정했다. **원인을 새로 알아낸 것이 아니라, 확인하지 않은 원인을 확인했다고 표시하지 않도록 한 수정**이다. 가격 데이터와 선정 결과를 바꾸지 않았다.

작업 전 저장점 `3e9a12f`. 사용자 포트폴리오의 기존 개행 변경은 제외·보존한다.

## 확인한 원인과 수정

- `strategy/event_explainer.py`: RULE_BASED는 모든 실패 연도에 업종 risk를 붙여 `~로 계절성 가설 무효화`를 출력했다. CURATED_TICKER도 출처 없는 `failed_causes` 또는 공통 매크로 문구를 사실처럼 붙였다. 어느 분기에도 해당 연도의 공시/수급을 조회·대조하는 절차가 없었다.
- 새 `research/failure_observations.py`는 연도별 월 수익률의 음수/0만 관측한다. `cause_status=UNVERIFIED`, `cause_sources=[]`이며 `원인 미확인`을 표시한다. 0은 보합이고, 결측/NaN/불리언을 0 수익률로 만들지 않는다.
- 과거 원인 지식베이스 필드는 보존하되 실패 원인 생성에 사용하지 않는다. 별도의 원인 증거 연결/심사는 이번에 구현하지 않았다.
- `_season_bundle()`의 응답 복사본도 새 관측 문구로 정리한다. 기존 불변 저장 파일 자체는 덮어쓰지 않는다. API의 선정 ID는 선정 모델 자료를 식별하며 응답 표현의 바이트 해시가 아니다.
- UI는 과거 `failed_analysis` 원문 대신 연도별 수치를 읽어 안전한 관측 문구를 만든다. 오래된 공개 파일에도 같은 화면 규칙이 적용되지만 공개 사이트 배포는 하지 않았다.
- 플레이북/설명 제목의 `실패 원인 정밀 분석`을 제거했다. 위험 조건은 `발생 미확인 가설`로, 원자재·환율 탓이라는 기본 문구와 근거 없는 비중 안내도 제거했다. 연도 카드 0 수익률은 보합, 결측은 자료 없음으로 표시한다.

- 관련 Python 회귀검사 **115 passed / 41.18초**, 디스커버리 별도 **8 passed / 2.30초**. 저장소 전체 또는 투자 성과 인증이 아니다.

- 작업 idle 확인 후 로컬 8790 재시작. 실제 API와 브라우저에서 설명 30개, `원인 미확인=true`, `~로 계절성 가설 무효화=false` 확인. HD현대일렉트릭 플레이북에서도 이전 원인 제목 없음 확인.
- 화면 자료: `output/playwright/stage5-cause-explanation.png`. Git 제외 로컬 산출물이다.
- 인수인계·데이터 검증 스킬로 인과 주장과 관측을 분리했고 Playwright로 실제 화면을 점검했다. 외부 뉴스/공시를 대조해 원인을 인증한 작업은 아니다.

## 5B: 실제 선취매 OOS를 위한 정확한 구현 순서

현재 기준모형(연도별 월/종료일 선택)을 기존 선취매 전체 전략과 혼동하면 안 된다. 코드상 장애물은 다음과 같다.

| 입력/규칙 | 현재 확인한 코드 경로 | 필요한 변경·합격 조건 |
|---|---|---|
| 검증 시점 | `discovery_engine.pattern_from_month_stat`: `pd.Timestamp.now().year`; 일부 계산에 `date.today()` | 모든 입력에 명시적 as_of 전달. 검증일 이후 가격·공시 변경 시 해당 시점 선정 불변 |
| 재무/모멘텀 | `seasonality._load_scored_map`: 최신 파일 우선 | 당시 이용 가능했던 공시 기준의 PIT 점수 저장본 필요. 없으면 입력 미확보로 기록하고 현재 점수 대입 금지 |
| 거래 가능 여부 | `rank_pre_entry_candidates` → `_clean_active_tickers`, `_latest_quotes` | 당시 상장/정지/관리/상폐 상태와 당시 가격 사용. 현재 생존 종목으로 대체 금지 |
| 선취매 순위 | stage 가중치 → seasonality_score → remaining_p50 → ticker/pattern | 생산 규칙을 동일 함수로 재사용. 각 fold에서 피크/진입/종료일/등급/순위를 과거 입력만으로 고정 |
| 설명 점수 | `event_explainer`: event_confidence에 따라 설명 점수 1/3/7/10점 | **계절성 점수에는 설명 신뢰도가 들어간다. 재무 Quant 점수와 다르다.** 과거 시점에 없던 지식베이스 사용 가능성을 별도 검토. 이번에는 순위 보존을 위해 배점을 바꾸지 않음 |
| 성과 | 원시 가격, 기업행위/체결·비용 검증 제한 | 선정 직후 가능한 체결 시점, 공식 거래일, 수정주가/기업행위, 상폐 정산, 거래비용 근거 없으면 verified 성과로 승격하지 않음 |

실행 순서:

1. PIT 입력 계약/준비 상태부터 만들고, 빠진 입력의 항목·기간·종목 수를 계수한다. 증거 없는 데이터는 현재 값으로 채우지 않는다.
2. 실제 생산 규칙의 시점 주입을 분리해 작은 고정 사례로 미래 데이터 변경 불변성·중복·무거래·상폐·연도 경계를 검사한다.
3. 고정한 과거 학습/검증 구간에서 전 종목 선정과 제외 사유를 기록하고 비용·체결 민감도와 함께 평가한다. 실패/입력 누락도 전체 분모에 남긴다.
4. 종목 선정의 실측 사후 장부와 재구성 백테스트를 구분해 UI에 연결한다. 이후 별도 미사용 기간과 다중검정·표본 불확실성 검사를 통과해야 성과 해석을 강화한다.

아직 남은 설명 감사: curated 이벤트 제목의 외부 근거, UI의 통계 명칭/임의 스트레스 시나리오와 생존 비율 표현, AI 브리핑의 원인·전망 단정. 이번 수정이 전 메뉴 설명의 완전한 검증을 뜻하지 않는다.
